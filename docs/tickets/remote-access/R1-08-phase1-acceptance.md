# R1-08 — Phase 1 验证环境与故障注入验收

- **仓库**：AgentDevClaw
- **决策依据**：[ADR-0008](../../adr/0008-remote-claw-connection-architecture.md)（全篇，尤其第 2、7 条）
- **类型**：验收与测试
- **前置**：R1-01 ~ R1-07 全部完成

## 背景

"稳"不是实现出来的，是验证出来的。Phase 1 需要一个可控的"远程"环境做日常开发验证（本地第二实例），加真服务器验收，加一套故障注入矩阵证明失败显式、恢复自动。

## 目标

### 本地第二实例验证环境

1. 同机启动第二个 Claw（不同 APP_PORT/VIEWER_PORT）；**数据目录必须隔离**——先查证现有用户数据目录（`~/.agentdev/AgentDevClaw`）是否支持环境变量覆盖，若无则补一个最小 env 覆盖（仅用于多实例/测试场景），避免两会话数据互串。
2. manual 模式验证全链路：`ssh -L 22101:127.0.0.1:1420 localhost`（或直连本地端口等价模拟），主实例添加 manual 连接指向第二实例。
3. 该环境沉淀为可重复的验证步骤文档（本地 docs，随工单附）。

### 故障注入矩阵

| 注入 | 期望 |
|---|---|
| 杀掉 managed SSH 进程 | 状态 → disconnected，退避重连，恢复后自动 connected |
| 停止远程 Claw（第二实例） | 隧道 up 但 target_not_found，UI 明示"远程 Claw 未运行" |
| 断网/禁用网卡 30s | ServerAlive 检测断开，恢复后零代码回到真值 |
| 版本不匹配（mock app_info） | connected + 警告标记，只读功能不受影响 |
| 配置中删除正在使用的连接 | 后续请求 target_not_found，UI 优雅降级不白屏 |
| 两条连接一条挂起 | 挂起连接独立超时，另一条与本地功能完全不受影响 |
| Phase 1 写操作（input/interrupt） | 本地服务端拦截 remote_write_disabled，远程零感知 |

### 回归底线

- **远程功能关闭（默认态）**：全量 core 测试绿；本地 sidebar/主视图/输入行为与 Phase 1 前一致。
- **开启且配置了连接**：本地 Agent 的所有行为仍与关闭时一致（本地路径零改动验证）。

### 真服务器验收清单

在用户现有远程服务器上走一遍：添加 managed 连接 → 握手 → 工作空间分组出现 → 打开远程 Agent 只读视图 → 消息流实时刷新 → 模板/Feature 面板渲染 → 断网恢复 → 断开重连。记录公网 RTT 下的轮询体感。

## 执行步骤

1. 查证并补齐数据目录 env 隔离（若需要）。
2. 搭建第二实例验证脚本/步骤。
3. 执行故障注入矩阵，逐项记录结果。
4. 单元测试补充：connection-store / tunnel-manager / connection-health / catalog-aggregator / 路由重写各模块（前序工单已要求，此处汇总确认覆盖率）。
5. 真服务器验收并回填清单。

## 验收标准

- 故障注入矩阵全部通过，无"静默失败"与"假成功"。
- 默认关闭态回归零差异。
- 真服务器验收清单全绿，公网环境体感可接受（轮询节奏下无明显卡顿）。

## 明确不做

- 不做性能压测与带宽优化（记录数据即可）。
- 不做跨平台 SSH 行为矩阵（Windows OpenSSH 为主，Linux/macOS 顺带验证）。
