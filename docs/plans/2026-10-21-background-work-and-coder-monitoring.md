# 后台接入与 Coder 非阻塞监视实施方案

日期：2026-10-21
状态：执行关联、通用后台接入、Bash 迁移与 Coder 非阻塞监视已实现；领域 Shell 组合已实现，按协议渲染的面板接入待实施。构建产物已更新，运行服务未重启；已有隔离 HTTP 验收，不替代在线冒烟。
决策依据：[ADR-0031](../adr/0031-background-work-and-domain-shell.md)

## 1. 目标与交付划分

使主 Agent 在派发 Coder 后能够继续工作，主动待命或自然结束轮次时让出执行权，由重要执行事件唤醒。同时将 Bash 已验证的通用挂起/唤醒衔接抽成薄的开发者接口，保留各领域的执行、监控和控制语义。

分为独立交付：

- **阶段 A：后台接入与双领域验证。**框架提供薄接入，Bash 行为保持，Coder 默认派发快速返回并登记监视，`watch` 改为待命意图；包含监视失联检测、教学与回归验证。
- **阶段 B：领域 Shell 命令组合。**阶段 A 验收后，单独实现多命令执行、逐条结果和条件执行。它不以后台能力为强依赖，不实现长脚本挂起续跑。变量、循环的范围另行设计，不由本计划默许。

阶段 A 不新建统一任务面板、不扩展业务验收管理，不修改线程配额、归档或自动接力的既有权威语义。

## 2. 实施状态与边界

### 已实现：执行关联基础与 Bash 迁移

- `CallTurnOptions.sourceRef` 随触发输入进入 `CallOutcome` 和 `turn.*` 事件；忙时同轮注入的输入通过 `consumedSourceRefs` 关联。完成、失败、取消均保留身份，CallArbiter 的多个执行段累积已消费身份；`pendingWakeups` 则取末段当前事实，不继承已过期的等待快照。
- 线程网关将进入线程域前的通知事件引用存为 `WorkThreadCommand.originSourceRef`。通知事件身份与后台工作身份分开：Bash 的 `sourceRef` 使用唯一事件 ID，`metadata.shell.taskIds` 保留聚合批全部工作 ID，`taskId` 保留末任务显示字段。后续观察器应结合来源、工作引用和生命周期事实对账，不以任意 `turn.completed`、idle 或 delivered 判断本次执行完成。
- `@agentdevjs/core` 导出 `BackgroundAccess`，收拢工作登记、pending-work 申报、一次性待命与注入投递器的衔接。`registerPendingWorkProvider` 返回按注册身份安全注销的句柄。核心循环没有增加 Bash 或 Coder 专用判断。
- Bash 已消费该接口。任务归属由创建该任务的接入实例捕获，通知按接收者分组；终态投递中或失败时保留未送达事实与主动补取路径。进程执行、输出游标、双节奏、关键词、ready、stdin、停止进程树及面板协议仍在 shell-feature。
- `bg_watch` 只在订阅当轮登记一次性待命，旧关键词订阅不再误停新用户输入；目标已结束或不存在时 `bg_tune(then=standby)` 返回现状，不空待命。

### 已实现：Coder 非阻塞监视

- `send` 提交后默认登记 `(threadId, commandId)` 监视并返回；`--dispatch-only` 明确只提交，旧 `--no-wait` 移除。提交回执与监视失效分别呈现，不自动重新派发。
- `watch` 查询保留执行历史、建立或复用观察，对仍在观察的目标登记一次性待命；已结束直接返回结果。可用 `--command=<commandId>` 精确选择提交。
- 观察器增量读取事件与 Inbox，关联 `sourceRef` / `consumedSourceRefs`、同会话的工作唤醒、明确的接续指令及 sessionChain；不以 idle 或 delivered 宣告完成。事件裁剪、删除、归档、取消、接力失败及进程失联分别报告。
- 通知走 ViewerWorker 的 reminder 输入队列，固定接收会话，未送达结果支持 watch 补取。Feature 快照仅保留监视目标，接续后一次性提示重建，不保存连接、不重新派发。
- 已有 local-features 构建、监视/HTTP/工具定向测试及 ACP 路由测试通过；运行服务仍未重启。

### 已实现：领域 Shell 命令组合

`;` / 引号外换行依次执行，`&&` 依据命令成功继续；管道依旧只传输出文本。整段语法、动词及参数先校验，执行结果保留每条回执、失败、条件跳过和终止后未执行的边界。进程内 adapter 返回字符串表示成功，失败通过抛错或 `{ ok, output, terminated }` 显式报告，基座不扫描文本猜测状态；GitHub adapter 将既有结构化错误转为失败。重定向真实读写 workspace 相对路径并检查符号链接归属。待命不截断工具调用，工具中断不回滚已发生操作，不保存脚本现场。

**后续边界**：面板协议接入独立实施，不以非阻塞监视或命令组合验收代替 UI 验收。

| `AgentDev/packages/core/src/core/workthread/bridge.ts` | 将指令 ID 作为 `sourceRef` 传入运行时 | 必须继续核验其到执行事件的关联链 |

实施前，`session-events.ts` 未携带输入 `sourceRef`；现已补齐触发输入和 busy 消费身份。仍不能只见任意 `turn.completed` 或线程 idle 就声明某次新指令已完成，特别是在线程忙时追加指令、挂起和接力的场景。

实施前，Bash 聚合通知以末任务会话选择接收者；现已按捕获的接收者分组，并以通知事件 ID 而非任务 ID 进入幂等输入链。

当前 Shell 结构层拒绝 `;`、`&&`，换行没有多命令语义；管道仅向下一段传文本并返回最后段。声明支持的重定向也没有完整执行语义。这些是阶段 B 的独立问题，不能用管道临时伪装批量调用。

## 3. 阶段 A0：编码前收敛接口与证据链

### 3.1 以行为定义薄接口

下面是需要形成的公开契约，不预设现有符号或最终函数名：

| 开发者动作 | 接入层责任 | 领域责任 |
|---|---|---|
| 登记待唤醒工作 | 返回可释放的登记，按所属 Agent/会话申报 pending-work | 提供真实标识与摘要，持有业务资源和观察器 |
| 提交通知 | 关联来源、接收者和事件，交给注入投递器；保留未送达事实 | 判定何时值得通知，提供内容及结果定位 |
| 结束观察 | 清理观察登记；完成事件与投递状态正确衔接 | 判定业务终态，释放领域观察资源 |
| 请求待命 | 在当前工具调用完成后的安全边界让出轮次，消费一次性意图 | 提供等待目标；目标已结束时先返回现状 |
| 销毁接入实例 | 释放自己的回调、定时资源和投递资源 | 决定领域资源是否应继续运行，不由通用层统一 kill |

必须覆盖以下时序：先完成后待命、登记期间完成、通知入队时模型仍忙、一次性待命被消费后新用户输入、任务结束但结果投递尚未成功。不得为了避免挂起而提前丢弃唯一未送达结果，也不得因旧待命标记误停下一轮。

共用机制不等于跨 Feature 共享业务权威状态。接口不得要求领域提供统一进度百分比、输出流或取消函数；不得通过通用 `cancel` 暗停外部业务。已有 `registerPendingWorkProvider` 的 source 覆盖语义要纳入多接入测试，避免一方覆盖另一方的登记。

### 3.2 核验模块和投递落点

先核对框架既有导出与依赖，再确定通用模块落点。默认不增加 npm 包或依赖层：若只需少量通用生命周期辅助，按 core 既有模块方式组织；若确需独立分发边界，再说明原因和依赖方向。无论物理落点如何，核心循环都只消费通用事实，不解释 Coder 或 Bash。

通知投递通过注入接口接到现有 reminder 输入链，保持 source/sourceRef、显式会话寻址与机器消息身份。不得把 Feature 面板通道、OS 桌面通知或直接重入 `onCall` 当成唤醒替代。没有可用投递器时明确接入失败，不静默回到永不唤醒的“后台成功”。

具体接口签名、投递成功的确认边界、重复通知处理及未送达保留方式，在实现首个公共模块前形成最小可测试契约；不承诺网络故障下的端到端 exactly-once 或持久队列。

### 3.3 核验 Coder 执行关联

完整读取提交 → Inbox → bridge → 输入队列 → runtime 事件 → board 的路径。验证指令在 busy、排队、自动接力和重复幂等提交下如何定位执行。若现有字段不足，只补实际需要的通用关联元数据，不在 core loop 增加 Coder 判断。

观察器使用现有事件与查询能力；传输选择由实际代码能力决定。可以在适配器内部使用有界、可清理的增量查询，不要求模型轮询，也不将查询频率等同于唤醒频率。若需要新增服务端推送，先验证已有通道是否能精确隔离并补齐快照对账，不为本次任务建设全局事件总线。

当关联无法证明时，显式报告监视无法可靠建立；不降级为“任何一次 turn 结束都算完成”。

### 3.4 核验接续检测载体

把“此前有待观察执行的意图记录”与“当前活跃观察器”分开。检查现有 Feature 快照/连续性和宿主启动信息是否足以携带最小检测依据；它只用于发现监视缺失，不保存 Promise、连接或计时器，也不恢复外部执行资源。

首次启动没有记录不得误报。接续后有记录无观察器时，向当前会话一次性提示重建，包含可恢复的目标信息；重建先查询终态。不能仅依赖 summary 恰好保留旧 thread ID，也不能向旧会话继续盲投。若现有接入点不足，先提交最小通用接口提案，不以 Coder 专用 react-loop 分支代替。

## 4. 阶段 A1：框架薄接入与 Bash 迁移

1. 在 AgentDev 仓库实现并导出最小后台接入契约，接到既有 pending-work 和安全待命边界，注入投递实现；保持无后台工作的普通对话行为不变。
2. 将 shell-feature 的共同申报、待命与唤醒衔接改为新接口，删除被替代的重复实现，不留下两套权威通知路径。
3. 保留 `bash` 前台预算、`bash_bg` 短结果捕获、进程树控制、输出与日志、独立增量游标、关键词和 ready 通知、双节奏及参数限制。
4. 确认 Bash 的终态通知优先于同时到达的周期通知；同源通知不重复，不同会话不混批。失败保留与主动查询补取仍可工作。
5. 回归 Claw 的 `PanelShellFeature`、强续让位、音效/完成通知与无头事件呈现，面板断开不影响唤醒。

此阶段 Bash 的工具面不改变。框架 build 产物验证与 Claw 装配验证都通过后，再接 Coder，避免同时调试两套尚未稳定的行为。

## 5. 阶段 A2：Coder 非阻塞监视

### 5.1 命令契约替换

| 入口 | 目标行为 |
|---|---|
| 正常 `send` | 返回真实提交/投递回执，默认登记本次执行监视，不等执行落定 |
| 明确仅投递方式 | 只提交，不登记后台监视；最终参数名在调用方盘点后确定，不把旧 `--no-wait` 自动解释成“不要监视” |
| `watch` | 查询/确保目标被观察；已落定直接回现状，否则登记待命并快速返回，在安全边界结束轮次 |
| `show` / `list` / `result` | 仍是主动查询与取证入口，不变成必须定期调用的监控循环 |
| `deliver` | 保持恢复 pending 指令的领域语义；不得当作恢复监视而意外重投 |
| `archive` / `unarchive` | 保持线程生命周期语义，不与取消监视混用 |

先盘点工具描述、技能、测试和其他适配器调用，确认是否存在必须维持的外部契约。没有明确契约则直接替换，不保留隐式旧版 fallback。阻塞型领域命令在通用基座仍合法，但 Coder 的推荐默认路径切换为后台监视。

短时 HTTP 提交仍受工具终止契约约束。“快速返回”指不等待 Coder 执行完成，不表示忽略服务端 READY 闸或把失败伪装成功。若响应丢失则保留结果未知，按幂等回执查询，不换键重派。

### 5.2 监视行为

- 以真实指令/执行关联建立观察，覆盖正常 head 接力和 `suspended` 后续唤醒轮；不得把接力中的中间落定误报完成。
- 默认通知完成、失败、需要干预的阻塞、监视失效。正常工具活动、正常接力不唤醒；不引入固定 20 秒汇报规则。
- 完成通知携带关联标识、实际终态和结果摘要/定位。末轮文本缺失时明确证据缺口，不捏造最终回复。结果内容的截断与落盘复用现有能力。
- 幂等重复 send/重复 watch 复用同一观察目标；一次终态不因重复登记而重复通知。同线程的不同提交分别关联，不能按 threadId 粗暴合并成同一次执行。
- 提交成功、监视失败分别报告，原任务不回滚、不自动重发；重新监视先查询最新执行现状，补取监视空窗内的结果。
- 线程删除、归档、接力失败、head 进程失联分别给出领域原因。单凭长期无新事件不能判死；内部网络错误与业务失败分别报告。
- 观察器退出只释放观察资源。停止 Coder 必须经原领域入口明确执行。

### 5.3 接续与教学

接入 A0 核验的最小失联检测。后继主 Agent 获得“此前监视未恢复，请查询并重新监视”的提示；其后由 Agent 调用领域工具重建，不透明恢复连接，不自动重发任务。普通用户消息不清掉仍有效的监视，旧的待命请求不跨轮误生效。

同步更新 `local-features/capability-shell/skills/claw-coder-dispatch/SKILL.md`、工具描述与帮助、实际引用监视纪律的提示词和文档。删除“必须一直阻塞 watch、落定前不能结束回合”的旧纪律，替换为“派发默认受监视、可继续工作、watch 表达待命、重要事件自动送达”。源码技能构建后再验证加载内容，不只改 dist。

## 6. 验证矩阵与阶段 A 完成条件

| 场景 | 必须证明的行为 |
|---|---|
| 无后台工作 | 普通轮次不受新接口影响 |
| 多来源并存 | Bash/Coder 登记互不覆盖，任一仍有等待时自然结束为 suspended |
| 登记后继续工作 | 不触发强制结束，不阻塞下一次模型行动 |
| 显式待命 | 工具完整返回后才让出；待命意图一次性消费 |
| 完成先于待命 | 返回现状或处理已入队结果，不永久等新事件 |
| 主 Agent 忙时完成 | reminder 正确入队，不并发重入主循环，不抢占当前工具 |
| 提交后即完成/提交时排队 | 本次结果不丢，旧轮完成不被当作新指令完成 |
| 幂等重复提交/重复观察 | 不重派、不新增重复监视和重复终态通知 |
| Coder 正常接力/挂起 | 跟随到本次真正落定，中间状态不误唤醒为完成 |
| 执行失败/需干预/监视失效 | 原因分清，能采取下一步，不用周期噪声代替故障通知 |
| 提交已生效但监视失败 | 两个事实均可见，重建不重发 |
| 用户插话/工具被终止 | 保留已发生操作，旧待命不误停新轮，不隐式停 Coder |
| 取消观察/销毁观察器 | 释放回调、连接和定时资源，不归档或停止 Coder |
| 多会话通知同时到达 | 按实际接收者分组，无串会话、无焦点 fallback |
| 投递失败/重复事件 | 未送达事实可查或补取，身份稳定；不宣称 exactly-once |
| 主 Agent 接续 | 有监视历史且失效才提示，首次启动不误报；重建取得空窗内终态 |
| Bash 回归 | 前台转后台、短结果、关键词、静默/周期、日志、stdin、kill 和终态通知保持 |
| 面板断开/切换会话 | 投影失败不影响执行与唤醒，原 Bash 卡片和控制正常 |
| 无头与完成消费端 | suspended 非失败，不产生伪完成音效/桌面通知，最终结果可交付 |

框架侧遵循现有 Vitest 体系；Claw 侧使用 node:test。模拟计时器、注入投递器和隔离数据目录验证竞态，禁止用真实长 sleep 或读真实用户线程文件证明正确性。涉及 WorkThread 状态/事件的新增场景同步映射到线程状态矩阵，不顺手改既有 F2 锁定行为。

完成条件：公共接口由 Bash 与 Coder 真正消费，重复共同逻辑已删除；上述矩阵通过；技能与工具契约一致；明确需要的构建、重启和冒烟记录齐全。不能只以公共模块单测通过宣布阶段 A 完成。

## 7. 阶段 B 的进入条件

阶段 A 验收后另行锁定语法范围。优先顺序是多命令序列及逐条输出，再到统一命令结果契约与 `&&`；重定向须修到真实有效或停止宣称支持。领域适配器显式报告命令结果，禁止基座扫描自然语言的 failed/timeout 猜成功。

测试至少验证：多次提交都执行且回执均保留；部分失败的已执行/未执行边界清楚；待命不会截断组合命令；工具终止保留已发生动作；条件判断以命令完成边界为准。循环与变量不默认进入本次交付，也不引入后台脚本恢复。

## 8. 发布、归属与状态维护

- 通用后台契约与 shell-feature 修改在 AgentDev 权威源码；Coder 监视、Claw 投递适配和装配在 AgentDevClaw。禁止只修 node_modules 或 dist。
- 新公共导出遵守按引用导出，不建立伞包，不新增反向依赖；模块/包命名由 A0 的最小接口核验确定。
- 开发态先构建框架，再构建 Claw local-features；框架 dist 改动后整体服务重启才生效。执行重启前单独确认，不在文档阶段操作运行服务。
- 文档阶段仅记录已接受决策与待实施方案；实现落定时更新 ADR 状态、权威使用文档和必要索引。ADR-0019 的历史文字保留，并指向 ADR-0031 的扩展边界。
- 阶段 A、B 分开验收与提交；不把后台接入通过等同于 Shell 批量语法已可用。
