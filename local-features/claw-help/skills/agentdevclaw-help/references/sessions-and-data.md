# 会话、上下文接续与数据

长对话必然遇到上下文容量上限。本产品的应对方式是「接续」：把早期历史折叠或压缩，产生一个带着必要记忆的新会话继续工作。这是使用智能编码空间最重要的心智——遇到提醒不要慌，按引导操作即可。

## 为什么主动控制上下文长度

模型标称支持很长的上下文，不代表应该放任它变长。长上下文有两个直接代价：

- **成本**：模型按输入量计费，对话每一轮都会把全部历史重新发给模型，历史越长，每一轮的费用越高；
- **质量**：上下文越长，模型的注意力越稀释——对早期指令的遵循、对细节的召回都会下降，表现为「聊得越久越健忘、越跑偏」。

定期把不需要逐字保留的早期历史精简掉，是在省钱和保质。

## 精简的频率：不是越勤越好

大模型服务商普遍有「前缀缓存」机制：如果这次请求的开头部分与上次完全相同，服务商直接复用已算过的结果，响应更快、费用更低。日常对话每轮只往后追加内容，开头不变，缓存持续命中。

精简会改变上下文的开头，缓存随之作废，之后的请求要按全价重算。频繁精简等于让缓存永远命不中，反而更慢更贵。

结论：两个极端都不划算——放任上下文无限增长浪费且降质，频繁精简破坏缓存优惠。**触发自动提醒时精简一次即可。**

## 超阈值自动打断是什么

会话上方状态条显示上下文用量。用量超过阈值时，「超阈值自动打断」生效：助手会在该时刻拦下一次输入，提醒你上下文已接近上限、需要先做精简。这是一次性的提醒（触发一次即完成使命，不会反复打断）；如不想被拦，可在状态条进度条旁的盾牌图标处关闭该功能，但上下文溢出后的行为将不受保护。

被拦住后的标准动作：对当前会话执行「精简」或「摘要」（见下节），然后继续对话。

## 会话精简与摘要：怎么做、怎么选

入口：左侧会话列表中**右键会话条目**，菜单提供：

- **总结历史（Summary）**：仅摘要 / 摘要并归档原会话
- **精简历史（Trim）**：仅精简 / 精简并归档原会话
- **分支**：从当前会话创建新分支

两种手段的区别：

| | 精简（Trim） | 摘要（Summary） |
|---|---|---|
| 早期历史怎么处理 | 对话文本保留，冗长的工具调用过程折叠成一行行注记 | 由模型改写成一份摘要 |
| 信息保真度 | 高（原文还在） | 有压缩取舍 |
| 适合 | 大多数日常情况，尤其是工具调用密集的编程会话 | 超长对话、只需记住结论与决定时 |

**选择建议：大多数情况选「仅精简」，直接确认即可，无需纠结。**

### 精简页面的操作

选择精简后进入精简页面，两种模式：

- **按比例**：拖动滑杆设定保留比例，页面实时预览保留区与精简区的内容；
- **按轮次**：指定从第几轮对话开始保留。

提交时可选组合：精简 / 精简并生成摘要 / 精简并归档原会话 / 精简、生成摘要并归档。

操作完成后得到一个接续的新会话，原会话默认保留在列表中（选了「并归档」则归档保存）。对话从精简点无缝继续，助手仍记得早期做了什么。

## 分支

右键菜单的「分支」从当前会话复制出一条新路径：想尝试另一种方案又不想丢掉当前进度时，先分支再改动，两条路径互不影响。

## 跨会话引用

想让新会话利用旧会话的成果，不必复述或拷贝内容——直接引用那个会话：

- **拖拽**：把左侧列表中的会话条目拖到输入框（引用挂到当前会话），或拖到另一个会话条目上（引用挂到那个会话，切过去后可见），显示为一个小标签（pill）；
- **菜单**：输入框旁的 + 菜单里也可以选择要引用的会话。

发消息时，助手能看到所引用的会话，并按需读取其中内容——先看会话概览，需要时再深入具体轮次，而不是一次性全文塞入。引用跨工作空间可用（例如在编程小助手里引用某个 Agent Studio 会话）。适合「接着上次那个话题继续」「参考另一个会话里做过的分析」这类场景。

## 数据存在哪

- **用户数据**：`~/.agentdev/AgentDevClaw/`（家目录下）。会话内容、工作空间状态、各功能的本地资产都在这里；备份或迁移机器时拷贝此目录即可带走全部数据。
- **你的项目目录**：助手只在项目目录内读写代码与配置（会话数据不写进项目目录）。
