# 界面导览

AgentDevClaw 的主界面分三个区域：左侧工作空间与项目列表、中部对话区、右侧工具面板。本文自左向右介绍各区域的构成与用法，每个功能点同时给出界面入口与背后的机制。

## 左侧：工作空间列表

左侧列表的顶层是工作空间，每个工作空间聚焦一类事，点开即进入对应的功能面。

### 智能编码空间（编程小助手）

主工作空间，用于和 AI 助手对话完成编程任务。在首页选择或输入一个项目目录后创建对话；助手在该目录内读代码、改代码、执行命令。会话按项目目录分组呈现（目录 → 会话两级），从列表点开任意会话即可继续历史对话。

### IM 渠道

把 QQ / 微信 / 飞书等 IM 平台的消息接入 Agent：在 IM 渠道工作空间配置各平台的接入线路，把线路路由到指定工作空间的会话，之后在 IM 里和 Agent 对话，回复自动传回 IM 平台。适合让助手在聊天软件里随时可用。

### Coder

无人值守的自主编码工作空间。Coder 不在界面上直接创建，由调度入口（命令行 `claw threads`、外部工具或对话调度）派发工单后自动运行。存在运行中或未归档的线程时，Coder 入口出现在左侧列表，点开可查看线程列表与执行状态。

### Agent Studio

开发与装配能力包（Feature）的工作空间。在里面用对话方式开发新的 Feature、验证并打包，供各个 Agent 装配使用。普通使用不需要进入。

### AgentDevClaw 指南

内置的使用手册，按目录组织成篇阅读（快速上手、进阶用法、新功能）。适合系统性了解产品；有具体问题时直接在对话里问本助手即可。

## 中部：对话区

对话区从上到下依次是：上下文状态条、消息流、输入框。

- **上下文状态条**：显示当前会话的上下文用量进度。当用量超过阈值时会亮起「超阈值自动打断」标记，含义与应对见 references/sessions-and-data.md。
- **输入框**：支持文本、粘贴图片；`/` 开头唤起命令菜单（技能与功能命令都在这里）；输入框附近可切换本会话使用的模型。

## 右侧：工具面板

右侧栏是一列图标按钮，每个图标对应一个面板；点图标展开，再点收起。

常用面板自上而下：

| 面板 | 名称 | 用途 |
|---|---|---|
| 任务 | 计划 | 当前会话的任务清单：助手执行多步骤工作时在此列出与勾销任务。每个任务带「执行到此处」按钮，点击后助手朝该任务推进执行，作用类似其他 Agent 的目标（goal）驱动——想让助手先完成清单中的某一项时用它 |
| 后台任务 | 后台任务 | 会话中转入后台长时间运行的命令（构建、测试、开发服务器等）的实时面板：输出流与运行状态；「打断」按钮终止任务，助手会收到用户手动打断的通知（知道是主动终止而非故障）；「立即汇报」按钮把当前运行情况即时发给助手，不必等定期汇报 |
| 功能特性 | 功能 | 当前会话装载的 Feature（能力包）清单与状态：每个 Feature 提供的工具、注册的钩子、运行时快照（检查器）。排查「某个工具为什么没出现」时先看这里 |
| 交互页面 | 交互页面 | 助手的可视化交互区：图表、表格、表单、按钮等结构化内容会显示在这里。对助手说「把结果用图表显示出来」，即可在交互页面查看 |
| 日志 | 日志 | 当前会话的运行日志，排查问题时按等级与关键词筛选 |

### 面板的自定义

右侧栏底部有「自定义」按钮（三个点图标），点开后的弹窗里可以：

- **开关面板**：关闭的面板从右侧栏隐藏；
- **拖拽排序**：按住每项的拖拽手柄调整顺序，右侧栏图标顺序随之变化。

右侧栏的图标本身也支持长按后直接拖动排序，与弹窗内的调整等价。自定义配置保存在本机浏览器中。

### 设置入口

右侧栏底部是齿轮图标（设置按钮），点开的菜单包含：模型配置、访问保护、全局 Feature 设置、工作空间、网络代理、用量信息、MCP 网关、退出程序。模型、代理、MCP 相关的配置入口见对应 reference（references/models.md、references/mcp.md）。

## 配置的三个作用域

能力（Feature）相关的配置分三个作用域，越具体的作用域越优先：

| 作用域 | 入口 | 影响范围 |
|---|---|---|
| 全局 | 设置 → 全局 Feature 设置 | 本机所有工作空间 |
| 工作空间 | 编程小助手的项目设置 → Feature 设置 | 该工作空间（编程小助手内还细分 agent 层与 coder 层） |
| 目录 | 编程小助手项目栏上的「目录设置」按钮（齿轮图标，打开项目后可见） | 仅该项目目录 |

同一配置项三层都设时，取最具体一层的值；少数追加型配置（如技能的额外目录）三层叠加生效。并非每个工作空间都暴露全部三层，但「全局 → 工作空间 → 目录」逐级覆盖是产品配置的统一思路。
