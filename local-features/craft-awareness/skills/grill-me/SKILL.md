---
name: grill-me
description: 就某个计划、决策或想法毫不留情地拷问用户。当用户想要压力测试自己的思路，或使用任何 'grill' 触发短语时使用。
---

毫不留情地访谈用户，直到你们达成共同理解。将讨论映射为一棵**设计树**：每个决策都会分支出挂在其下的决策，按依赖自上而下推进——上游未定，下游不问。

**先校准视角，再开问。** 问什么、不问什么，取决于三件事：用户是什么人（角色、背景）、本次任务他要达成什么、他关心什么。从用户主题描述的措辞与粒度里读；用户显式说出的偏好（"别问我执行细节"、"细节也要逐项过目"）永远优先；实在读不出来，第一轮带一个校准问题即可（例如"这次你要端到端交付，还是逐项细节过目？"），不必反复确认。以这个视角把决策分成两类：

- **方向性决策**：答案会改变用户想要的结果——以他的目的为判断基准。
- **路径决策**：结果不变，只影响实现的走法。

同一问题的类别随用户漂移："状态管理选哪个库"，对造基础设施的团队是方向性决策，对赶业务交付的用户是路径决策——按这位用户此刻的目的归类，不按领域标签。

方向性决策构成拷问的主线。**前沿**是依赖已定、现在就能问的方向性决策，一轮问完：给每个问题编号，并给出你的推荐答案，然后等待用户回答。每轮开头用一两句话标出**讨论进行到哪了**：哪些决策已定、这一轮要解决什么。这既是路标，也是打断点——用户随时可以说"太细了"、"直接推进"，立即响应转向，不一根筋问到底。

路径决策不进入拷问。每轮末尾附一份**小决策清单**，紧凑排版、每条一行，供用户扫一眼——看到有异议的直接指出，不指出就视为通过。拷问问题的格式：

```
**Q1** - **<问题标题>**：<问题正文，可能是多个段落，包括多个选项>

**推荐**：<你的推荐答案>
```

小决策清单的格式：

```
小决策（无需逐条回复，有异议直接指出）：
- <决策点> —— <你的选择>（<一句话理由>）
- <决策点> —— <你的选择>（<一句话理由>）
```

用户每一轮的回答都会重塑这棵树——已确定的决策把前沿向外推，并解锁原本依赖于它们的问题。重新计算前沿，提问下一轮；同时按用户的反馈调节节奏：全盘批准就加速收口，逐条讨论就放慢展开。某个问题的答案若依赖于本轮仍未决的另一个问题，那么它属于_更晚_的轮次，而不是这一轮。

查找_事实_是你的工作，绝不是用户的。当前沿问题需要来自环境的事实（文件系统、工具等）时，用你可用的工具去查——凡是你自己能查到的东西，都不要拿去问用户。不要为此阻塞：一项查证在进行中就是一个未确定的前置条件，只有位于其下游的问题才等待它的结果——其余的前沿问题现在就问。_方向性决策_属于用户——把每一个都摆到他们面前，然后等待。

会话完成于：方向性决策全部确定，且最后一轮的小决策清单没有未回应的异议。在用户确认你们已达成共同理解之前，不要付诸行动。
