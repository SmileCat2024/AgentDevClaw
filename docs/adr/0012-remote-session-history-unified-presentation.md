# ADR-0012 — 远程会话历史的统一呈现与激活语义

- 状态：Accepted
- 日期：2026-08-30
- 关联：ADR-0008（远程连接架构）、ADR-0010（侧栏统一投影）、ADR-0011（protoclaw 远程写适配）

## 背景

Phase 1 之后，侧栏叶子 = 运行中会话（ADR-0010），远程运行中会话已并入统一投影。但远程机器上的**历史会话**（已持久化、未运行）在本地不可见、不可打开、不可管理——用户必须到远程机的界面操作，破坏"只是额外打开了远程主机的目录"的心智。

Phase 3 引入远程会话历史时，出现三个交互契约决策，涉及未来读者会困惑的"为什么没有来源标记/确认层/分页"。

## 决策

### 1. 历史会话进 workspace surface 统一混合呈现，侧栏保持纯运行时

远程历史会话与本地历史会话在**同一个 workspace surface 的会话列表**混合排序，列表项不做来源分区、不加远程徽标。侧栏（ADR-0010 投影）不因此改变——叶子仍只是存活 runtime，历史会话索引不产生侧栏层级。

- 替代方案（rejected）：远程目录组下加"历史会话"子区——使侧栏出现第二层会话列表，破坏"目录组下只有运行中会话"的投影语义，且与本地历史会话的呈现位置分裂。
- 后果：打开某个目录的 workspace，看到的是这个目录的全部会话，不区分它在哪台机器。数据层的命名空间 id 足以在需要时恢复来源感知，呈现层零远程分支。

### 2. 激活远程历史会话无确认层

点击远程历史会话 = 调用与本地完全相同的激活流程（activate → 目标宿主启动 runtime）。远程会话的激活发生在远程机器上，但**不加**"将在某主机启动会话"之类的确认层。

- 理由：用户显式点击历史会话的意图就是继续它；远程机本来就是跑会话的机器，启动成本与本地同量级；确认层会让前端出现"远程特殊流程"，违背本地/远程一致原则。
- 替代方案（rejected）：远程激活二次确认。重开条件：未来接入稀缺共享主机（资源成本敏感的场景），按连接级 capability 加确认，属独立决策。

### 3. 会话列表照本地全量模型，不做分页

远程历史会话列表沿用本地 `readSessionIndex` 的全量读取模型，不设计分页协议。

- 理由：两端是同一产品形态，会话量同量级；链路一致优先。
- 重开条件：单目录会话量达到数百级、真实体感卡顿时，分页作为独立增项落地，不改当前数据形状。

## 后果

- 前端所有会话列表/上下文菜单消费点必须以"host 级命名空间 id"统一寻址（见 R2-01 的身份来源核对清单），不允许出现"这是远程所以走另一套列表/确认"的分支。
- 远程激活的副作用（远程进程启动）由既有失败契约兜底：连接断开/远程不可达时按 ADR-0011 三分类显式呈现，不静默排队、不伪装成功。
- 语义上，"会话激活（session activation）" 成为跨本地/远程的统一概念（见 CONTEXT.md）。
