# 046 — 项目改绑、归档与明确删除

状态：已实施并完成定向验收；整批端到端验收见 [047](047-ph-project-coexistence-acceptance.md)。
仓库：AgentDevClaw。前置：[045](045-ph-project-selector-and-chat-ui.md)。
共同契约：[目录对话与项目对话并存](2026-10-22-ph-project-coexistence.md)。

## 目标

项目管理只影响该项目，不能因为工作目录相同影响目录对话、其他项目或其运行实例。已有会话后续使用项目新目录，工作文件不自动移动。

## 实施

1. 改绑使用项目 ID 定位，检查项目相关会话是否有执行中轮次；存在时明确拒绝本次改绑，不强行打断或排队偷偷生效。
2. 空闲但已存活的项目实例也必须处理：保存必要状态，按现有单 Session 移除/停止机制释放旧实例，再在后续使用时按项目新目录装配。不能仅更新项目表并直接复用旧 runtime；不能为了一个 Session 杀掉有其他成员的共享进程。
3. 完成改绑后返回明确成功状态，前端刷新有效目录、Git 等文件视图与当前项目展示；Session 身份及消息保持不变。失败不得报告已生效或自动用旧目录继续一次。采用现有输入/生命周期协调方式，确保改绑与新输入没有在旧实例执行的窗口；不建设通用事务框架。
4. 日常项目归档/恢复与永久删除分开。归档保留会话、配置与工作文件，项目可恢复；不要自动把 Session 档位当成项目归档状态。
5. 永久删除前展示影响范围并明确确认，按项目 ID 枚举目标 Session/配置与托管资产，复用现有 Session 删除及清理机制。外部目录始终保留；托管目录是否删除由用户明确选择，默认不捎带删除。
6. 如果托管目录已经被其他项目或目录对话引用，不得自动删共享工作文件；需明确告知并保留目录。改绑离开的旧托管目录不自动清除，不扫描清理“看起来没用”的文件。
7. 不调用原按目录批量删除项目的路径处理独立项目；原目录删除仍只影响目录对话，前票已有隔离回归。

## 主要入口

041 项目 store/API、`agent-startup.js` 与现有单会话停止/移除链、`agent-lifecycle.js`、`scripts/run-prebuilt-agent.js` 的 SessionLifecycle、Session 删除与索引清理，前端项目操作与确认弹窗。完整阅读共享进程退出/兄弟会话处理后再改，不猜测 stop 函数的作用范围。

## 验收

- A/B 与目录 D 共目录、共享进程：A 有存活空闲实例时改绑，下一条 A 输入使用新目录；B/D 实例及配置不受影响。
- A 执行中改绑被拒绝，项目记录和有效目录未改变；不存在“记录已变、下一轮还用旧目录”。
- 改名不改 ID，改绑不搬工作文件；旧消息和 Session ID 保留。
- 归档/恢复不丢历史；永久删除 A 不删除 B/D，会话关联缓存按既有机制清理。
- 外部目录永不删除；托管目录删除需明确选择且不能误删其他归属引用的文件。

## 边界

不引入目录对话改绑或项目间转移，不修改其他工作空间生命周期，不通过杀整进程或新增 fallback 规避旧 runtime 复用问题。只用隔离测试资产验证删除，禁止在用户真实目录运行验收。
