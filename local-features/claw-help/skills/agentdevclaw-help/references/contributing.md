# 源码参与引导

用户想阅读源码、用源码版运行或参与开发时，按本文引导。本文只做引导，不复述仓库内容——仓库自身的认知地图（AGENT.md）会在正确的工作目录里自动生效。

## 先弄清运行环境

用户可能运行在两种环境之一，回答源码相关问题前先判断：

- **桌面版**：安装包安装，应用文件在安装目录，本机通常没有源码仓库；
- **源码版**：从仓库克隆后 `npm install && npm run build && npm start` 启动，项目即源码。

判断不了的直接询问用户，不要默认。

## 两个仓库

| 仓库 | 职责 |
|---|---|
| https://github.com/SmileCat2024/AgentDevClaw | 产品壳层：Web 界面、各工作空间的预制 Agent、服务端 |
| https://github.com/SmileCat2024/AgentDev | 框架：Agent 核心、LLM 接入、技能与能力包体系 |

日常使用与功能问题多数落在 AgentDevClaw；框架行为（Agent 生命周期、会话、日志体系）在 AgentDev。

## 参与路径：在仓库目录里打开助手

关键一步：克隆仓库后，**在仓库目录里重新打开助手**（或其他 AI 编程工具也可以）。项目根目录的 `AGENT.md` 会被自动读取注入，它就是为「AI 助手进入本仓库」准备的完整引导——架构地图、权威文档索引、开发与协作规范都在里面，之后的一切跟着它走即可。

在别的目录里打开助手是读不到这份引导的，这是新手最常踩的一步。

## 常见诉求的引导

- **想用源码版运行**：克隆仓库，按仓库 README 的安装与启动步骤操作（Node.js 环境 + npm 三段式：install → build → start）；
- **想阅读 / 修改某处代码**：先在仓库目录里打开助手，让 AGENT.md 的索引体系接管定位；
- **想给自己的助手开发能力包（Feature）**：不必碰源码——用 Agent Studio 工作空间对话式开发、验证、打包，详见左侧 Agent Studio 入口；
- **想报告问题**：按 references/troubleshooting.md 的报告清单提交 Issue。

## 操作纪律

- 克隆位置、分支选择听用户的指挥，不替用户决定；
- 下载与安装属于有影响的操作，执行前先说明将做什么；
- 用户未提出参与源码时，不主动引导 cloning。
