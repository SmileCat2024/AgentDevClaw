## 模型配置

Agent 的所有能力都由大模型驱动，您需要先添加至少一个模型，才能让 Agent 正确运行。AgentDevClaw 支持三类接入方式：**订阅型**（Codex、OpenCode，登录即用套餐内模型）与 **API 密钥直填**（兼容 OpenAI Chat Completions、Responses、Anthropic Messages 三种主流协议），可以按需组合、随时切换。

### 1.打开模型配置

1. 点击右下角的设置按钮（齿轮图标）。
2. 在弹出菜单中点击「模型配置」。

![打开模型配置](./assets/model-config-entry.png =75% left)

模型配置页按用途分为「总览」「Codex」「OpenCode」「自定义模型」「语音识别」等标签。首次配置可从总览页的快速配置入口开始。

### 2.添加模型：按获得模型的方式选择入口

模型配置页顶部的「快速配置」区提供三个入口，对应三种典型情况。

**使用 Codex 模型（ChatGPT 订阅用户）**

连接 OpenAI 账户，使用 Codex 订阅套餐支持的模型。点击入口进入 Codex 标签页，点「管理账号」进入账号管理页。Codex 支持同时保存多个 OpenAI 账号：点「添加账号 · 浏览器授权」或「添加账号 · 设备码」登录新账号——浏览器授权要求当前环境能够访问浏览器并完成 OpenAI 登录；设备码登录可在其他设备打开登录页并输入页面显示的代码。账号列表中每行可重命名、登出，点「设为当前」即可在账号间切换：切换后所有 Codex 模型统一走新账号，正在运行的会话也会在下一条消息自动换用。登录成功后，目录中的模型点击即可添加。

![Codex 模型目录与登录入口](./assets/模型设置.png =85% left)

![浏览器授权与设备码登录](./assets/Codex登录方式.png =85% left)

> [!IMPORTANT] 先配置网络代理
> Codex 的服务在国内网络无法直连。请先完成[网络代理](#5网络代理)配置，再进行登录，否则登录会一直无响应。

**使用 OpenCode 模型（OpenCode 订阅用户）**

点击入口进入 OpenCode 标签页，在顶部填入 OpenCode API Key（输入即自动保存），即可浏览并添加目录中的模型。服务档位 Zen / Go 对应不同的端点与计费方式，按您订阅的档位选择。

**添加自定义模型（持有 API 密钥）**

适合直接从模型服务商购买 API 的用户。在「自定义模型」标签页点击右下角「添加模型」，填写连接信息：

| 字段 | 说明 |
| --- | --- |
| 名称 | 自己好认的名字，如「智谱 GLM-5.3」，与API请求无关可以随便命名 |
| 接口协议 | Anthropic / OpenAI Chat / OpenAI Responses |
| Model | 模型 ID，如 `glm-5-turbo`，这是API请求发往后端的模型名，需要严格按照供应商指南填写 |
| Base URL | 服务地址，从模型服务商处获取 |
| API Key | 服务商签发的密钥 |

在接口协议下拉框中，还可以使用 OpenCode / OpenAI Auth 两种方式进行登录，两者底层分别使用 OpenAI Chat 和 OpenAI Responses 协议连接。

表单下方还有三组可选项：

- **模型能力**：模型支持深度思考或图片输入时，打开「启用思考」「启用视觉输入」开关；
- **生成参数**：上下文长度、压缩阈值、输出上限、温度，留空走默认值；
- **高级**：自定义请求头，部分服务商网关需要。

### 3.激活与切换

添加后点击模型卡片即可激活为全局默认，顶部横幅会显示当前生效的预设。

对话进行中也可以随时更换：点击输入框中的模型选择器，为当前会话选择其他模型，立即生效、无需重启。切换只对当前会话生效，不影响其他会话与全局默认。

设置窗口内还有「语音识别」标签页，用于配置语音输入的识别模型，用法与上述相同。

### 4.按角色指定模型

编程小助手工作空间支持按角色指定模型：在工作空间卡片上点击「工作空间设置」，可为「编程小助手」「Coder」「系统管理」分别指定模型；不指定则跟随全局默认。

![按角色指定模型](./assets/智能编码空间模型配置.png =75% left)

### 5.网络代理

设置菜单中的「网络代理」为整个应用配置全局代理：启用后，服务端所有网络请求与 Agent 子进程都经由该代理发出，主要服务于 Codex 等需要代理才能访问的模型服务。

配置步骤：点击设置菜单 →「网络代理」→ 打开「启用代理」开关 → 填写代理地址（如 `http://127.0.0.1:7890`）。面板会自动检测系统代理，检测到时可一键填入。建议先点「测试连通性」确认可达，再点「保存并应用」。

保存后代理立即对服务端生效；正在运行的 Agent 会话需要重启该会话后才经由代理发出请求。

![网络代理设置](./assets/网络代理配置.png =75% left)

### 6.常见问题

**Q1：我修改了模型配置，会话里的 Agent 会跟着变吗？**

会。API Key、Base URL 等连接信息发生变化时，正在使用该配置的运行中会话会自动收到刷新并使用新配置，无需手动干预。个别会话若未及时生效，可在输入框的模型选择器中点击配置名称手动刷新。

**Q2：为什么模型输出经常会被中途打断？**

请仔细检查模型生成参数是否填入合适的思考、输出token值。输出token值指的是思考token+后续正文输出/工具调用的token总量预算上限

**Q3：模型配置的URL端点不对？**

您需要关注模型供应商提供的端点后缀情况要求，特别是带不带 `/v1`的问题。在AgentDevClaw中，Anthropic 协议的 baseUrl 带不带 `/v1` 都行；OpenAI 系协议（chat / responses）必须自己带 `/v1`
