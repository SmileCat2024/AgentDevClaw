# MCP 配置

MCP（Model Context Protocol）是连接外部工具的开放协议：文件系统、数据库、浏览器、公司内部系统——凡是提供 MCP 服务器的工具，都能接入 AgentDevClaw，Agent 即可直接调用它们的能力。MCP 的配置分两层，按「配置跟着谁走」区分：

| 配置层 | 入口 | 适合 |
| --- | --- | --- |
| 共享 MCP 网关 | 设置 → MCP 网关 | 本机全局共享的 server；连接集中托管，状态可查、可重启 |
| 项目级配置文件 | 会话目录下 `.agentdev/mcps/` | 跟着项目走的 server，可提交进版本库、与团队共享 |

两层可同时使用。为同一个服务选择一条路径，避免重复启动。项目配置文件之间同名 server 会加序号后缀；项目配置与网关同名时，当前实现采用网关条目，建议使用不同 ID 区分。

日常使用优先选网关层：连接状态和错误在界面上直接可见。项目级 server 连接失败时界面上没有提示，排查难度更高。

## server 配置的关键字段

配置文件建议显式写明传输类型：

- 本地进程型：`"transport": "stdio"` + `command` + `args`（可选 `env` 环境变量）；
- 远程服务型：`"transport": "http"`（或 `"sse"`）+ `url`。

项目级文件也支持用 `type` 代替 `transport`，下文示例采用该写法；网关 API 使用 `transport`。

**项目级 stdio 条目必须显式写传输类型**：包裹格式缺失时连接会误入 HTTP 分支并报 Invalid URL，单对象格式缺失时文件会被忽略。经网关界面添加时默认选中 stdio，不受此影响。

## 全局：共享 MCP 网关

打开设置 →「MCP 网关」：

- **系统内置服务**：随产品提供的服务（Claw MCP、Debugger MCP 等），界面上直接开关启用；
- **自定义服务器**：「+ 添加服务器」→ 填写服务器 ID、传输类型（stdio / HTTP / SSE）；stdio 型填命令与参数（每行一个，可选环境变量 JSON），http / sse 型填 URL。添加后立即尝试连接，对本机所有工作空间的会话生效，不必逐项目配置。

服务器 ID 就是工具名前缀，工具形如 `mcp_<ID>_<工具名>`。

列表中如显示「错误」，点进该 server 详情可看具体原因（例如它依赖的本地程序没启动）；修好后点「重启」重试。错误状态的 server 不会进入会话，必须修好并重启连接后才可用。

也可以直接让助手代配：在对话里说清楚要接入什么，助手会调用本机网关 API 完成添加并验证连接。

## 项目级：`.agentdev/mcps/`

在**会话绑定的目录**（新建对话时选择的那个项目目录）下创建 `.agentdev/mcps/`，每个 server 一个 json 文件。文件内容支持三种写法：

**写法一：`servers` 包裹（标准格式）**

```json
{
  "servers": {
    "my-server": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "some-mcp-server"]
    }
  }
}
```

**写法二：`mcpServers` 包裹（Claude 格式）**

```json
{
  "mcpServers": {
    "my-server": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "some-mcp-server"]
    }
  }
}
```

**写法三：单个 server 对象（文件名即 server 名）**

```json
{
  "type": "stdio",
  "command": "npx",
  "args": ["-y", "some-mcp-server"]
}
```

> [!TIP] 从 Claude Code / Claude Desktop 迁移
> 把原配置里 `mcpServers` 的内容保存为 `.agentdev/mcps/` 下的 json 文件即可；唯一的改动是给 stdio 条目补上 `"type": "stdio"`（Claude 配置里通常没有这个字段）。

配置文件在会话首次运行时加载并连接，每个会话独立启动自己的 server 进程。新增或修改后，新开对话生效；已开着的对话要等重启产品后重开。

项目级 server 的连接状态不显示在 MCP 网关面板里；验证它是否生效，最直接的办法是在对话里让助手调用它的某个工具。

## 确认 server 已生效

按三个层次检查：

1. **配置已加载、工具已注册**：右侧栏「功能」面板中出现 `mcp_` 开头的工具；网关层还能在设置 → MCP 网关查看连接状态。
2. **实际调用成功**：让助手调用只读工具，确认拿到目标应用的数据。仅显示「已连接」、工具数量大于 0，仍不足以证明业务操作可用。
3. **所需能力可用**：涉及素材读取、编辑、导出时，分别验证所需环节。写操作应在单独测试文档和新输出路径进行，避免覆盖已有文件。

桌面桥接型服务有两段连接：`助手 → MCP CLI → 桌面应用`。桌面程序没启动或控制端口不匹配时，CLI 仍可能成功列出工具，但调用会失败。检查 MCP 参数与启动快捷方式的端口、凭证是否一致，以及素材和输出是否在应用授权目录内。

如果应用明确拒绝某种命令，换一个端口或重复配置不能解决。助手应说明限制；需要改用无界面模式或脚本时，先与你确认操作方式的变化。

## 常见问题

**加了 server 但工具没出现？**

检查 json 文件是否在会话目录的 `.agentdev/mcps/` 下、MCP Feature 的目录扫描或网关开关是否开启、会话是否在配置之后启动、传输类型是否显式填写、`command` 在本机是否可执行。网关层另外检查状态与工具数。

**工具有了，却仍然不能操作？**

查看实际工具返回的错误。`connection refused` 通常指向应用未启动或端口不匹配；路径越界需核对应用授权目录；`disabled` 或 `unsupported` 需查应用的模式与命令限制。外层调用成功只说明收到了回复，回复里的业务失败仍然需要处理。
