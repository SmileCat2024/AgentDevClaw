# v0.2.4 更新公告

本次更新涵盖自 v0.2.3 以来的全部改进，包含 200+ 次提交。

**这次更新，可以先试三件事：开一段长对话，让它在上下文快满时自动接力；把零散的对话整理进项目；选中回复里的关键句，加一条高亮标注。**

本版本把编程小助手的对话升级为连续的对话链：上下文快满时自动接力，手动精简也在当前对话内完成，列表按对话聚合、历史一键回看，存量对话在升级后自动归并。对话可以归属到「项目」，与目录双轨组织；新建对话可选容器模式，在隔离环境中运行（实验性）。IM 渠道的线路改为绑定对话，支持多线路并发连接。模型选择跟随对话传递，Codex 支持多账号登录；对话文本可标注、可导出。会话索引迁入数据库，长列表更流畅；接续、输入、列表与通知中的一批问题得到修复。

- **编程小助手对话链**：上下文超过阈值自动接力（默认开启）、精简原地完成、列表按对话聚合、历史存档回看、存量对话自动归并
- **项目**：对话归属项目，目录与项目双轨组织，侧栏分组与「移动到」整理
- **容器模式**（实验性）：新建对话可在隔离容器中运行；Coder 可配置执行模式策略
- **IM 渠道**：线路绑定对话，多线路并发连接，任务结果自动回流
- **模型**：模型选择跟随对话传递；Codex 多账号登录与全局切换
- **标注与导出**：对话文本高亮标注；对话导出为 Markdown / HTML
- **列表与阅读**：会话索引迁入数据库，翻页更快；归档对话可直接打开阅读；搜索支持范围过滤与排序
- **桌面**：安装包减小约 100 MB，`.env` 配置文件统一支持

## 编程小助手：对话从「一次会话」变成「一条对话链」

一段对话不再因为上下文变长而断裂成列表里的多行。本版本起，对话是一条连续的链：精简、接续都发生在同一条对话内，列表一行就是一段完整对话。

### 上下文快满时，自动接力

- 顶栏用量条旁的上下文保护开关升级为三档：**关闭 / 自动打断 / 自动接续**，循环点击切换；新的对话默认使用「自动接续」
- 选择「自动接续」时，上下文用量超过阈值后，编程小助手会等当前步骤完成，自动整理上下文并由接力会话继续，对话不中断、页面不跳走，过程由顶栏「上下文接力中…」提示
- 「自动打断」保持原有行为：超过阈值后打断，等待你的下一条输入作为继续的批准
- 会话控制面板顶部新增接续策略选择：**自适应 / 纯精简 / 纯摘要**，与 Coder 同款；改选对下一次接力立即生效

### 手动精简留在当前对话

`/trim`、`/summary` 与精简配置页保留，行为改为对话内接续：整理后的对话（精简主干或摘要）作为当前对话的开头继续，滚动位置、草稿与输入焦点不动，不再跳转到「另一个会话」。精简页不再提供「归档原会话」选项——历史改由对话内的存档自动承载。

### 历史存档与列表聚合

- 列表一行就是一段对话，显示最新一段的标题、预览与时间；对话行提供「历史」入口，按时间倒序查看每次精简之前的完整对话原貌，标注当时的整理方式与规模
- 历史存档只读，可以从任一历史节点「从这段继续」，分出一条新对话
- 「移动对话」按整条对话链移动（含全部历史），不再只移最新一段

### 存量对话自动归并

升级后首次启动会自动分析既有会话的接续与分支关系，把同一链路的会话归并成一条对话，已归档的会话也一并纳入。有歧义的关系不会被强行合并——宁可多出一条「没有历史的对话」，也不猜错归属。

## 对话归属项目：目录定位，项目归档

目录决定对话在哪里运行，项目给对话一个稳定的归属。现在可以把同一件事的对话收进一个项目里。

- **新建项目**：在目录区的「新建项目」入口选择目录创建，项目绑定目录
- **双轨组织**：新建对话时分别选择运行目录与所属项目；不选项目时，对话归在目录的默认集合下
- **「移动到」整理**：会话列表多选后移动到其他项目或目录；执行中的对话会等空闲后再移动
- **侧栏项目分组**：同一项目的对话归到一组，按项目名显示；目录与项目列表按最近使用排序

## 容器模式：在隔离环境中运行对话（实验性）

把鼠标悬停在会话列表的「新建对话」按钮上，会展开运行模式菜单：**普通模式**（直接在当前主机运行）或**容器模式**（在隔离容器中运行）。

- **会话固定模式**：对话按创建时选择的模式运行并持久化，容器运行失败时如实报错，不静默回退到本地
- **Coder 执行模式策略**：在「Coder 策略」页选择标准 / 容器 / 由 Agent 按任务选择；通过调度创建工单时也可以显式指定
- **容器镜像管理**：智能编码空间设置新增「容器镜像」页，查看环境状态、镜像清单与构建日志
- **最小暴露**：容器内只挂载工作区与运行必需的数据，模型与 Agent 配置以只读方式提供，白名单之外的宿主数据不进入容器

**容器模式是实验特性**：需要本机安装 Docker；容器会话与本地运行中的会话互斥，启动容器对话前需先停止本地对话，反之亦然。

## IM 渠道：一条线路，一条连续对话

IM 线路的绑定从「某一次会话」改为「一条对话」，渠道连接与消息路由都跟随对话链。

- **绑定不断线**：绑定的目标对话发生精简、接续或换代，线路连接与消息投递自动跟随，不再因会话更替而悬空
- **多线路并发**：同一门户可以同时连接多条线路，各自绑定不同对话
- **可绑目标更广**：任意工作空间的活跃对话都可以绑定，包括 Coder 任务线程
- **接线员也用连续对话**：接线员以唯一对话连续承接门户消息，换代后旧对话归档可查
- **任务结果自动回流**：绑定的任务线程执行完成后，结果经门户自动发回 IM；同一消息重复推送不会重复处理

**升级提示**：既有线路绑定与门户渠道选择在升级后清空，需要重新接线；旧接线员会话归档只读保留，不做换算。

## 模型选择：跟着对话走

- **选择随对话传递**：切换模型与思考强度成为对话自身的状态——接续继承当前选择、分支从源对话的当前选择出发、回滚内容不改变模型、停止后重开与服务重启后恢复所选
- **切换即改当前对话**：在输入框切换模型，只影响正在查看的对话，不再波及同时运行的其他对话
- **Codex 多账号**：设置 → 模型配置的 Codex 页签变为账号列表，可添加多个账号、重命名、一键切换当前账号或登出；既有登录自动识别为第一个账号
- **更多供应商选项**：Codex 新增速度档位；OpenCode 新建模型与自定义模型共用同一份默认值

## 标注与导出：留住对话里的重点

### 文本标注

选中对话中任意一段文字，从浮动工具条创建标注，也可以直接复制选中内容：

- 高亮显示在原位；点击高亮，同一条标注的多个片段联动亮起，可查看与删除
- 新选区与已有标注重叠时自动合并为一条
- 右栏「标注」面板集中查看当前对话的全部标注
- 标注保存在会话中，重新打开对话时仍然在

### 导出对话

对话标题的悬停弹窗中新增「导出」：选择 Markdown 或 HTML，默认只导出用户与助手的正文，勾选后包含完整过程；由浏览器选择位置保存文件，不支持的浏览器自动转为下载。

## 列表更快，归档可读，搜索更细

- **会话索引迁入数据库**：升级后首次启动自动完成迁移；会话很多时，列表翻页与新建对话都更快
- **归档对话直接打开**：列表中的归档对话点击即可阅读，消息、图片与工具卡片照常渲染，无需启动对话进程；历史存档的「查看原文」打开后停留在原文，不会被自动带回最新
- **搜索更细**：历史搜索支持按范围过滤（全部 / 未归档 / 已归档）、按相关性或最近排序，长结果分页加载
- **预览更有信息量**：会话列表的预览优先显示助手回复正文，而不是工具结果

## 其他调整与升级提示

- **任务面板显示交付物**：任务卡片以副行展示「交付」内容，完成标准更直观
- **Agent Studio**：Feature 详情新增「技能」页签，技能以卡片呈现，可进入阅读页查看全文
- **侧栏布局自定义**：左侧工作空间列表支持拖动调整顺序、在分组之间归置，折叠状态与布局跨刷新保持
- **界面配色**：强调色从靛蓝调整为薰衣草色系
- **安装包更小**：桌面安装包减小约 100 MB
- **`.env` 配置**：桌面版与源码启动同样支持 `.env` 文件配置端口等参数，真实环境变量优先
- **Agent 行为**：系统提示词重写，技能激活、外部文本与接续场景的处理说明更完整；后台任务面板在多个来源同时输出时保持稳定，滚动位置不再丢失
- **问题排查**：崩溃后日志保留进程号、运行时长与内存采样记录，报告问题时更容易定位原因
- **`grill-me` 技能**：追问改为一次问完一组问题，编号跨轮连续，便于逐条回应

## 问题修复

### 对话接续

- 修复 Coder 任务以摘要方式接续时停在接续界面、反复提示「正在启动新会话」的问题，手动接续入口恢复可用
- 修复接续期间补充的指令静默丢失的问题
- 接续完成后，视图自动跟随到新对话，不再停留在已结束的旧对话上
- 重启与接续后，对话的标题与归属保持稳定，不再漂移

### 列表与侧栏

- 删除对话后，条目不再以「正在删除」的状态短暂重现；删除与关闭操作有即时反馈与视图回退
- 新建对话在启动失败时如实报错并回滚，不再留下打不开的空对话

### 输入与消息

- 修复回退编辑按钮消失、陈旧输入覆盖新状态的问题
- 消息不再等待辅助数据才渲染；错误分组显示后，后续消息不再错位
- 发送消息时，时间分隔线的插入不再引起页面向下跳动

### 通知

- 任务失败与取消时如实提示，不再把接续打断误报为「已取消」
