# v0.2.0 更新公告

本次更新涵盖自 v0.1.9 以来的全部改进，包含 220 次提交（另含 AgentDev 框架仓库同期 100+ 次提交），是 AgentDevClaw 迄今规模最大的一次版本更新。

本轮更新的底色是**底层框架的正式换代**：内测期的 `agentdev` 单包整体退役，拆分为 `@agentdevjs` 组织下的多包体系并正式发布 npm——Claw 从此克隆即跑，不再依赖相邻源码仓库。在此之上，产品沿五条主线扩张：

- **智能编码空间与 Coder**：编程小助手工作空间升级为双身份形态，新增无人值守自主编码身份 coder，以工作线程（WorkThread）承载跨会话的长任务接力，并经 ACP 适配层接入编辑器
- **Agent Studio**：对话中开发 Feature、装配 Agent，在隔离的 Test Runtime 中验证，快照进入用户 Feature 仓库——打通「制造 → 验证 → 消费」全链路
- **`claw run` 直调体系**：无工作空间、不依赖 server 的轻量 Plain Agent，stdout/stderr 严格分流的五种输出格式与 jsonl 会话事件流
- **Slash 命令与 Capability 控制面**：框架能力注册表统一 Agent 控制入口，`/` 唤起的动态命令菜单
- **产品体验**：Git 源代码管理面板、共享进程模式、Feature 配置多作用域三态编辑器、工具执行进度实时展示

## 底座重塑：AgentDev 框架正式发布 npm

### `agentdev` 单包退役，`@agentdevjs` 多包体系上线

旧 `agentdev` 包是全量捆绑形态：core、19 个 feature、agents、模板打进一个 dist，`better-sqlite3`（原生编译）、`sharp`（原生二进制）、OpenAI SDK、MCP 三件套等重依赖全量携带——只用基础能力的宿主也要承担全部安装成本与原生编译失败率。本版完成破坏性拆分：

- **框架四包**：`@agentdevjs/core`、`@agentdevjs/llm`、`@agentdevjs/viewer`、`@agentdevjs/mcp` 锁步发版。core 达成零原生依赖、零重 SDK、零 feature 反向依赖，可被第三方单独依赖
- **生态 Feature 包**：shell、websearch、qqbot、weixin-bot、lsp、memory 等 14 个生态 feature 成为独立 npm 包，按需引入；QQ 协议实现内化进 qqbot-feature（vendor），不再依赖未发布的第三方包
- **AgentDev 仓库**转为 npm workspace monorepo，CI 门禁强制执行依赖纪律（core 永不依赖 feature 包）
- 旧的 `agentdev` 包名已在 npm 标记 deprecated

**对使用者的直接影响：克隆即跑。** `npm install` 直接从 registry 拉取正式包（自带构建产物），不再需要相邻的框架源码仓库参与构建。框架联动开发可选开启开发态（`npm run agentdev:local` 以 junction 链接相邻仓库，`npm run agentdev:published` 切回），两种形态由依赖声明自动判定，构建脚本按形态分流，无需手动干预。

启动流程同步升级为 **install → build → start 三段式**：`npm start` 前置的 preflight 会自动校验依赖链接、自动补装缺失依赖、自动重建过期的本地 Feature 构建产物。`git pull` + `npm install` + `npm start` 即完成升级，无需手动执行任何构建命令。

### 运行时范式升级

框架侧完成多项范式层调整，Claw 侧零债务跟进：

- **静态 Hooks 唯一契约**：Feature 钩子从装饰器改为静态声明（`static hooks = { ... }`），显式声明 observe / guard / transform 语义；`inject` 声明驱动挂载拓扑排序（自动环检测）；`reloadFeature` 支持热替换（任一阶段失败自动回滚旧实例，工具启停等用户决策在热替换后存活）；会话裁剪改为 tombstone 归档——被 trim 掉的消息不再物理丢弃，可精确恢复
- **工具终止协议「中断即结果」**：工具超时与用户打断不再伪装成失败。执行器在终止信号后给工具最多 1 秒优雅收尾，窗口内返回的结果携带已有部分输出并标注 `interrupted` 结构化字段（区分 timeout / user）；超时统一归框架管辖，工具以声明式 `timeout` 契约声明超时值，模型传参可覆盖。Shell 命令超时不再丢输出
- **结构化调用终态**：每次调用的终态以 `CallOutcome` 结构化表达（状态 / 原因 / 错误类别 / statusCode / 可重试标记），框架错误信息不再依赖文本前缀协议；LLM 重试等待经通知暴露，前端运行状态与 CLI 输出同步消费
- **模型调用策略与网络等待硬化**：模型配置新增 `maxRetries` / `timeoutMs`（缺省为框架默认：10 次重试 + 5 分钟总期限）；web_fetch 声明 30s 超时契约，LSP 全部查询请求加 15s 超时——慢目标与挂起的语言服务器不再阻塞整个回合
- **统一日志体系**：Agent 运行时日志 hub-first 路由（DebugHub 优先，无 ViewerWorker 连接时自动 fallback stdio，审计不丢失）；无头模式下全量日志走 stderr，stdout 只承载结果协议行；agent 侧代码接入 ESLint `no-console` 强约束，绕过 logger 的输出从此被静态检查拦截
- **会话存储原子写入**：会话快照落盘改为 tmp + rename，进程崩溃不再产生损坏的会话文件

## 新特性

### 智能编码空间：编程小助手 + Coder 双身份

编程小助手工作空间升级为「智能编码空间」，一个工作空间承载两个会话身份：

- **编程小助手（main）**——交互式编程 Agent，完整工具链与全部既有能力不变
- **Coder**——新增的无人值守自主编码身份。会话不是由用户手动创建，而是由调度面（ACP 编辑器、`claw threads` CLI、外部脚本）创建；上下文接近压缩阈值时自动执行「带摘要精简 → 接力新会话」的线程轮换，长任务持续推进直至交付，不需要人在场

**工作线程（WorkThread）** 是 coder 的承载模型：把一串先后接力的会话认定为同一项工作的连续性锚点（`sessionChain` / `headSessionId` / 接续挡板 / 指令暂存 Inbox）。核心体验：

- **交接无缝**：会话精简 / 摘要 / 轮换期间，新输入自动进入线程 Inbox 暂存（输入框呈现暂存气泡），交接完成后自动投递到新会话——「精简后想补一句“请继续”」不再需要等新会话建好再手动切过去
- **分支即新线程**：从线程中的任意会话分叉，产生的是独立的新线程，语义干净不互相缠绕
- **会话连续性框架化**：trim / summary / 组合精简全部切换为消费框架官方变换实现（Claw 侧精简引擎净删约 3000 行），摘要生成从「起一个完整 agent 子进程」降级为进程内 LLM 注入，更快更稳
- **归档即事务**：线程归档是生命周期事务（先中断运行时再归档），已归档线程拒绝新指令，取消归档恢复看板

**线程即调度对象**：coder 的调度不绑定特定工单系统，线程本身就是通用的调度与执行单元——外部编排方（ACP 编辑器、`claw threads` CLI、脚本）经线程创建、投递指令、读取事件增量。会话上下文轮换升级为线程驱动的通用服务：head 会话阻塞时经其线程自动解析轮换，失败封存为结构化状态。coder 装配了 implement / TDD / code-review 三套流程规范技能，按规范约束自主交付。

**`claw threads` CLI**：终端内完整的线程操作面——list / create / show / events / send / deliver / advance / handoff-failed / resume / close / archive / unarchive，事件流支持 jsonl 增量读取。

Web UI 左侧新增 coder 线程列表投影（同一工作空间下的线程视图）；coder 首页是极简线程看板——状态徽标、接续链（第 N 棒、trim / 摘要计数）、最新执行事件、待处理指令与恢复 / 关闭操作。coder 拥有独立的模型预设与 Feature 配置组设置。

### ACP 适配层：把 Coder 接进编辑器

新增 **ACP（Agent Client Protocol）v1 适配层**，外部 ACP client（编辑器插件、CLI 工具，如 Zed）可以经 stdio JSON-RPC 直接驱动 Claw 的 coder：

- `claw acp coder` 启动独立 stdio 适配器进程，只做协议转换与本机 HTTP 调用——不实例化 Agent、不读内部数据，执行权威完全留在 Claw server
- 方法集覆盖 `initialize`、`session/new`、`session/prompt`、`session/cancel`、`session/list`、`session/resume`、`session/load`（历史回放，把既有会话投影给编辑器）、`session/close`（转发线程归档）；出站通知 `session/update` 流式推送过程
- 会话发现按工作目录定位既有线程，续接急切挂载，编辑器重启后无缝续上
- 适配器进程退出只释放自身内存映射，不停止、不删除任何 Claw 持久化对象

### Agent Studio：对话中制造 Feature 与 Agent

悬置的 feature-creator / agent-creator 时代结束，新的 **Agent Studio** 工作空间以「对话即制造」的方式开发 Feature 与装配 Agent：

- **dev agent 只做控制面**（`studio_*` 工具集），被测对象跑在隔离的 **Test Runtime 子进程**中，以 `studio-sandbox:<项目名>` 出现在左侧 Agent 列表——可看不可输入，运行过程完全透明
- **两种运行模式**：`feature-harness`（最小 Agent + 开发中 Feature，聚焦单 Feature 验证）与 `agent-debug`（真实 Agent 装配 + 仓库 tgz 底座 + 开发源码覆盖，验证完整装配行为）
- **状态机由运行证据推进**：`implemented → mounted → verified → snapshotted`，每一步都有对应的运行记录落盘，不接受口头宣称
- **不可变快照**：验证通过的 Feature 打成内容寻址 tgz 写入用户 Feature 仓库（`~/.agentdev/AgentDevClaw/user-features/`），同版本不同字节直接拒绝——验证过的东西不可再被悄悄改动
- **标准 npm Feature 项目**：脚手架生成 kebab-case 命名的标准项目（src/ → dist、tsup 构建），与生态包同构

支撑这条链路的是**共享 Feature Runtime 解析链**（schemas → catalog → resolver → provisioner → loader）：Studio 里验证过的装配，与 `claw run` 消费端运行时走同一条解析链——「Studio 验证过的 = 消费端运行的」由架构保证，而非流程约定。

### `claw run`：Plain Agent 直调体系

与工作空间平行的第三种 Agent 形态：不建工作空间、不依赖 Claw server，一条命令直接调用：

```bash
claw agents                           # 列出可用 plain agent
claw run <name> --goal "修复这个 bug"   # 单次调用
claw run <name> --goal "..." --headless --format jsonl   # CI / 脚本场景
```

- **监视 / 无头双模式**：默认连接 ViewerWorker，会话在 Claw 面板「已连接」中实时可见；`--headless` 完全不连，适合 CI。连接失败自动降级无头继续，不报错
- **stdout/stderr 严格契约**：过程信息（reasoning、工具执行渲染、运行日志）一律走 stderr，stdout 只承载结果数据，任何格式下都可安全管道化
- **五种输出格式**：`result`（单行协议 JSON）、`text`（人类可读）、`json`（全量结果）、`quiet`（仅响应正文，可 `| jq`）、`jsonl`（codex exec 风格会话事件流，机器实时消费全过程）
- **注册制**：`claw agents register <dir>` 接入任意独立 Agent 项目（Studio 开发的 Agent 可关联 Studio 项目启用 `--debug` 源码覆盖）；release 默认按 metadata 声明的精确 tgz 版本解析，与消费端共享同一条 feature-runtime 链
- 支持会话续接（`--session`）、指定工作目录（`--cwd`）、运行后保持存活（`--keep-alive`）、临时配置组（`--config-group`）

### Slash 命令系统与 Capability 控制面

输入框键入 `/` 唤起命令菜单——这是新统一控制面的入口。框架引入 **Capability Registry**：Feature 经 `getCapabilities()` 声明自己的可控命令（参数 schema 复用 Feature 配置词汇表），注册表统一提供 invoke / query / emit 三动词契约与 `entryPoints` 访问控制，替代此前每个 Feature 各写一套「前端模块 + HTTP 路由 + IPC 分支」的四件套。

- **动态菜单**：命令清单按当前 agent + 会话实时拉取（`GET /protoclaw/commands`），自动聚合宿主域与会话域命令，断连 runtime 优雅降级到宿主子集
- **invoke 型命令**：选中即执行；带参数的命令弹出参数表单，回显当前运行值、按需提交（dirty-only），执行结果 toast 反馈
- **prompt 型命令**：选中只挂 pill，不立即触发；激活随发送的消息以结构化字段（`capabilityActivations`）流动，经输入队列、线程交接到达任意后继会话——显示归显示、触发归状态，不依赖文本解析
- 内置 `/trim`（全量精简）与 `/summary`（仅摘要）两条宿主命令

### Git 源代码管理面板

右侧面板新增 Git 面板（与功能面板同级，跟随当前会话的项目目录）：

- **更改区**：工作区状态列表，悬停显隐的 stage / unstage / discard 行内操作，commit 输入框；discard 分路处理（untracked 清除 / modified 恢复 / staged 先 reset），带强确认
- **提交历史**：SVG 泳道图（经典槽位泳道算法，支持线性 / 分叉 / 合并 / octopus 合并），分支 / 标签 / 远程胶囊，author 与相对时间；点击行展开该提交的文件清单
- **分支区**：本地 / 远程分支列表，支持切换、新建、删除（未合并分支二次确认）；图形区可按分支过滤历史
- **Stash**：save / pop / drop
- 上下双区布局，分隔条拖拽调高并持久化；概况条常驻当前分支与远程关系

### 共享进程模式

编程小助手默认启用 **shared-by-project** 进程模式：同一项目目录下的多个会话共享一个 Agent 进程，而不是每会话一个进程。同项目下开多个对话时启动更快、内存占用显著降低；会话列表以 SHR / ISO 徽标区分进程模式，可在工作空间设置中切换。进程内各会话的身份隔离与中断路由由框架保证（中断按 agent 身份精确投递，不会误伤同进程的兄弟会话）。

### Feature 配置：多作用域三态编辑器

全局 Feature 配置从独立工作空间并入设置菜单，升级为**多作用域三态编辑器**：

- **作用域层叠**：编程小助手按「全局 → 项目目录 → 会话」三层队列合并（目录层随会话的项目自动匹配）；coder 按「全局 → 配置组」合并
- **三态渲染**：每个配置项呈现「出厂默认 / 继承（标注继承自哪一层）/ 覆盖（左侧标记条 + 上游值对照）」三种状态
- **diff-only 保存**：只提交本次编辑碰过的字段，构成稀疏层内容；值与上游相同时提示二选一（清除覆盖 / 保留固定）
- 单字段「重置为继承」按钮；配置组不存在时显式报错，不做静默回退
- CLI 侧配套 `--config-group` 临时覆盖与 `claw config-groups` 只读查询

### 可观测性升级

- **工具执行进度实时展示**：命令执行等长任务工具执行中在对话区实时显示进度阶段与尾部输出，不再是黑盒等待（框架 `tool.progress` 通知，100ms 节流）
- **工具与 Hook 运行时开关**：Feature 面板中可对单个工具、单个 Hook 执行启用 / 禁用，立即生效，用于运行时排障与能力收敛
- **反向钩子面板重设计**：单层卡片结构（生命周期分组 + 时间线行式条目），observe / guard / transform 语义色徽标，中英文 hover 提示，折叠状态跨轮询记忆
- **日志面板重设计**：固定头部 + 列表内滚动，轮次徽标（R3.2）一等显示，warn / error 整行淡底；结构化数据默认截断 4000 字符按需展开（展开态记忆），增量渲染替代全列表重建，搜索 180ms 防抖，支持按轮次筛选
- **运行状态显示重排**：底部指示块按步骤计时，输入框旁胶囊显示本轮运行时长；流式构建中的工具名实时呈现
- **装配预检面板**：调试侧栏新增装配预检（preflight）面板，对假想装配做四项检查（错误 / 警告分级呈现并附修复指引），dry-run 展示挂载拓扑链、工具归属与 Hook 清单——装配错误在启动前即可发现
- **右侧面板自定义**：面板可见性开关与拖拽排序，配置持久化

### 其他新特性

- **Todo 未完成计划自动继续**：会话恢复时未完成的计划自动接续推进，不再需要手动提醒
- **强制继续（Force Continuation）**：新会话级 Feature，在模型输出被 max_tokens 截断且无工具调用时自动注入续跑提示，长输出任务不再需要人工点「继续」；触发条件与连续接续上限（默认 5 次）均可调，右侧面板提供控制开关
- **带摘要的精简（Trim + Summary 组合）**：精简早期历史的同时在保留边界处追加摘要，兼顾上下文释放与关键信息留存，成为 coder 线程轮换的默认变换
- **OpenAI OAuth 登录体验**：选择 OAuth 协议后无需先手动保存预设（点击登录自动保存）；编辑已保存预设时立即加载登录状态；设备码一键复制（含局域网访问降级方案）
- **上下文用量条实时化**：contextLength / compressRatio 改经 overview 实时通道同步，会话切换与模型热切换后即时准确
- **Generative UI 组件扩展**：新增 11 个组件（累计 20+），组件目录经技能声明可被 Agent 自主发现
- **编程小助手提示词新增「成品视角」章节**：交付物（代码、commit message、文档）按「没参加过这次对话的人能否看懂」的标准书写

## 调整

### 架构治理

- **本地显式资源寻址**：前端到 Agent 的全部控制请求收敛为显式三元组寻址（agentId / runtimeId / sessionId，runtimeId 优先），移除服务端 `current agent` 语义——页面焦点前端化，只持久化到 localStorage，不再参与服务端寻址。这是为未来接入更多执行端（远程 / 多主机）预铺的地基
- **探索代理与子代理退场**：编程小助手收敛为 main + coder 双身份，探索会话、子代理派生及其调度目标整体移除；`claw` CLI 的 explorations / spawn 等旧命令随之退役（线程体系与 `claw run` 是它们的正式继任者）

## 问题修复

以下均为 v0.1.9 及更早版本中存在的问题：

### 输入与焦点（user input 链路治本）

输入框通讯是历史高频出 bug 的区域，本轮做了一次根治性修复：

- **会话身份被动漂移**：外部入口（IM / CLI / 调度）创建会话会抢占服务端 host 级激活态，导致前端输入签名突变、输入面整块重建（失焦、录音保护失效、草稿写错槽位）。引入 viewer 会话绑定，把「用户正在查看的会话」与服务端激活态解耦
- **输入面重建丢焦点**：重建完成即恢复焦点与光标位置（仅当焦点原本在输入区内）
- **提交竞态幽灵复活**：提交链路 await 期间输入面重建后，清空的是脱离 DOM 的僵尸输入框，已发送文本经草稿回写复活；改为提交成功后重新解析实时输入框，先清 DOM 再删缓存
- **运行胶囊计时泄漏**：模块级计时状态切会话不清理，导致时长显示错误

### 会话与侧栏

- **侧栏会话状态投影三处误报**：临时加载提示归属到错误项目分组；归档 / 删除历史会话时侧栏凭空出现条目；会话已生成但侧栏仍显示「精简未完成」（混淆了会话已提交、运行时启动中、viewer 未就绪三个事实）
- **会话导航**：新建会话后自动切入；归档 / 删除后跳转到同项目最新会话，不再停在空态
- **AI 会话标题身份统一**：标题生成不再误用其他会话的上下文；摘要生成超时可取消，不再堆积悬挂进程

### 消息渲染与滚动

- **消息块折叠时机契约重写**：旧机制按固定索引窗口在滚动停止后判定，忽略行像素高度——比视口高的长块快速上滚时永不折叠。新契约为运动帧 / 落地结算 / 后台补丁三个时机，各自明确折叠权限，长块落点直接呈现折叠块 + 视口锚定
- **跟随最新与切回滚动的三处协调缺陷**、**聊天区滚动与导航跟随**：快速滚动、模式切换、流式追加场景下的跳变与错位
- **hljs 缺失时工具结果源码破坏消息列表结构**；**欢迎页切换闪烁**与窄容器横向溢出
- **精简后折叠控件丢失**：折叠工具活动摘要等系统消息带标签保留，精简后消息块折叠控制保持可用

### 其他

- **群聊写入与轮询串行化**：并发写入与轮询竞态导致的群聊数据异常
- **归档运行时清理与会话变更解耦**：归档操作不再误触发会话数据变更链
- **read 工具去重在会话接续后不重置**：精简 / 摘要产生的新会话里读取同一文件被错误跳过（框架侧修复）
- **微信 bot 日志洪泛**：会话失败时 getUpdates 循环刷屏日志（框架侧修复）
- **Context Guard 阈值锚定实时模型元数据**：热切换模型后阈值即时跟随新模型的上下文窗口
