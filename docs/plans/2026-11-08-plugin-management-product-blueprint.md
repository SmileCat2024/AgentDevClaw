## 1. 概念模型

三层术语（自上而下）：

- **插件（Plugin）**：用户拿到的一个 tgz 包，是导入、装配、处置的唯一单位。
  内部至多三个面——**工具面**（agent 调用的能力，即 feature）、**UI 面**（右栏面板）、
  **数据面**（给面板供数的服务路由）。
- **feature**：插件工具面的组成单元，只在运行时视图（右侧 Features 面板）呈现，
  不再是用户操作的宏观单位。
- **builtin 官方可选插件**（playwright-shell、lsp 等）：无包形态，宿主代码内置，
  只有选装开关——与 tgz 插件是并列的两种来源，统一出现在插件页，视觉上以来源徽章区分。

**装配层级 = 可见性层级**（三级体系）：

| 级别 | 怎么装 | 面板出现在哪 |
|---|---|---|
| 全局级 | 全局设置里安装 | 所有界面（任何工作空间、含工作空间首页） |
| 工作空间级 | 各工作空间插件页安装（现状唯一路径） | 该工作空间内的界面（含它的首页） |
| 对话级（跟 runtime 硬匹配） | 装配时声明跟随对话（形态待定） | 只在打开对应对话/runtime 时右栏显示 |

配套原则：

- **作者声明的 scope 降级为装配建议**：作者说"这是跨空间工具，建议装全局"，
  实际可见性由用户装到哪一级决定（"插件只交素材、处置权在工作空间"原则的延伸）。
  例：agentero 声明 global scope、只装配在编程小助手时，面板不应出现在其他
  工作空间——是否处处可见取决于装配层级，不取决于声明。

## 2. 存储全景

| 数据 | 存储位置 | 归谁管 | 现状 |
|---|---|---|---|
| 插件包本体（tgz） | 官方区 `resources/features/` + 用户区 `~/.agentdev/AgentDevClaw/user-features/` | 仓库（Claw 层） | ✅ |
| UI 面资产 | `user-features/assets/<包>/<版本>/`，版本化 URL serve，digest 纪律 | 仓库自动解出 | ✅ |
| 数据面代码 | `user-features/server-env/<包>/<版本>/` | 仓库自动解出 | ✅（懒解出自愈待补） |
| 装配声明（$mount） | 配置树层文件：全局级写 global 层、空间级写 agent 层、对话级待定 | 配置体系 | 空间级 ✅；全局级机制通缺入口；对话级 ❓ |
| 插件参数 | 同一棵配置树四层：global → workspace → project → directory | 配置体系 | ✅（settings 契约已定：JSON Schema properties 包装） |
| 面板偏好 | 服务端 KV，键 = 工作空间 × 面板 ID | 各工作空间 | 🔨 全新契约（panelPrefs） |
| 呈现配置（显隐排序） | 服务端，随工作空间走（替代 localStorage） | 各工作空间 | ✅ 已落地（2026-11-08 第二批） |

关键设计：装配、配置、呈现是三棵不同的树，但装配声明与插件参数共用配置树文件
（$mount 是配置树里的特殊键）——不另立存储。

## 3. 界面入口全景

1. **全局设置（右下角设置按钮）→ 插件区** 🔨
   - 插件仓库视图：已导入插件列表、上传 tgz（三面摘要确认后入库）、删除 tgz
     （前置：无任何层级装配引用）
   - **全局级装配**：把插件装到全局级
   - 全局默认配置（配置树 global 层编辑）
2. **工作空间设置（各 APP 内）→ 插件页** 🔨（骨架现为商店）
   - 共享货架（仓库全部插件）+ 本空间装配清单；卡片三态：未装配 / 已装配 / 已禁用
   - 重卡片视觉：三面摘要 + 版本 + 装配/禁用/卸载动作
   - 卡片「设置」→ 插件设置弹窗：manifest 渲染表单 + 作用域切换（全局默认 / 本空间覆盖）
3. **对话打开后（对话级插件）** ❓
   - 对话级装配的面板只在打开对应对话时出现在右栏
   - 工具面参数天然吃到 project/directory 层（会话有目录上下文）
4. **右栏 rail**
   - 面板本体：点开即用（懒装载）
   - 自定义弹窗（三点按钮）：显隐 + 拖拽排序 → 呈现配置
5. **右侧 Features 面板（运行时视图）** 🔨 待视觉分层
   - 轻条目列出当前 agent 实际挂载的 feature 实例，标注来源
     （"内置" / "来自 agentero v0.3.0"），只读，点来源跳插件页卡片
6. **Agent Studio（制造端）**
   - 对话开发插件 → 快照打包 → 入同一仓库；其仓库浏览视图与本体系对齐 ❓（现状概念冲突）

## 4. 配置三层体系

| 配置类 | 例子 | 用户在哪配 | 存在哪 | 谁声明 |
|---|---|---|---|---|
| **插件参数** | vault 路径、功能开关 | 工作空间设置 → 插件「设置」（或 Feature 配置分页） | 配置树四层（分层：全局默认→空间覆盖→项目/目录） | 作者（manifest settings） |
| **面板偏好** | 每页条数、视图切换、列宽 | **面板本体上的设置控件** | 服务端 KV，纯空间级（工作空间 × panelId 隔离） | 作者（面板内自绘控件，经 host.panelPrefs API 读写） |
| **呈现配置** | 面板显隐、右栏排序 | 右栏自定义弹窗 | 服务端，纯空间级 | 宿主 |

分层与否是刻意的：参数需要跨空间统一治理（分层），偏好和布局是空间私事（不分层，
每个空间从零开始自己长，不存在全局默认）。

按面寻址（同一份插件参数，三面各看到哪几层）：

- 工具面：全四层（会话有目录上下文）——现状
- 数据面：global + 装配层合成；**面板请求由宿主注入当前视图的工作空间标识**，
  数据面按请求上下文合成——"编程小助手的面板读 vault A、Coder 的读 vault B"由此定义
- UI 面：只读，经数据面接口取合成值，不开第三条写通道

给作者的分界约定：影响多面或服务端行为的进 manifest settings；
只影响本面板怎么画的进 panelPrefs。

panelPrefs 契约（新增，随 #6 呈现配置同款基础设施实现）：claw-host 协议扩展
`host.panelPrefs.get()/set()`，宿主负责存储、多空间隔离、跨设备一致。

## 5. 工作空间持有清单（概念模型闭环）

一个工作空间在插件体系里持有四样数据：

| 数据 | 内容 | 特点 |
|---|---|---|
| 装配清单（$mount） | 挂了哪些插件、什么版本 | 空间自主处置的锚点 |
| 空间层参数覆盖 | 配置树 workspace 层的插件参数值 | 插件参数分层体系的空间层 |
| 面板偏好 | 每面板一份 KV | 纯空间级 |
| 呈现配置 | 面板显隐排序 | 纯空间级 |

## 6. 全生命周期

| 阶段 | 动作 | 关键语义 | 现状 |
|---|---|---|---|
| 制造 | 独立仓库（adv-plugin 模式）或 Studio 对话开发 → tgz | | ✅ |
| 导入 | 全局设置上传 tgz → 三面摘要确认 → 入库 | 只入库不激活；digest 纪律 | ✅（入口现挂商店面板，待迁全局） |
| 装配 | 三级：全局 / 工作空间 / 对话 | 装配层级 = 可见性层级 | 空间级 ✅；全局级、对话级 🔨/❓ |
| 配置 | 卡片「设置」或 Feature 配置分页 | 一份配置树两个视角 | ✅（设置弹窗入口 🔨） |
| 使用 | UI 面即时 / 数据面即时 / 工具面随下次新会话 | 生效边界明确 | ✅ |
| 禁用 | 卡片三态之一 | 声明配置全保留、三面整体下线、随时回来 | ✅ 服务端层已落地（2026-11-08 第三批；API 面 `install {enabled:false}`，UI 呈现待产品方案） |
| 升级 | 导入新版 → 多版本并存 → 装配改指新版 | 各面按各自边界切换；环境按 digest 重建 | ✅ |
| 卸载 | 卡片卸载 | 声明置 null、配置留在层文件、三面退场 | ✅ |
| 删除 | 仓库删 tgz | 前置：无层级装配引用 | ✅ |

## 7. 现状冲突清单（本体系落地要消解的）

1. **商店混层**：货架卡片与右侧 Features 面板共用 feature-card 结构，
   插件（装配单位）与 feature（运行时单元）视觉不分层。
2. **入口重复**：上传 tgz 入口在商店面板（工作空间设置深处），全局级装配无入口；
   与"导入是 Claw 级仓库动作"的定位不符。
3. **Agent Studio 自带 Feature 仓库面板**：与统一插件仓库概念冲突，归并方式待定。
4. **数据面配置取 identities[0]**：多空间装配时"第一个装配身份统治"，
   与按请求上下文合成的目标语义不符。
5. **呈现配置在 localStorage**：不随工作空间、不跨设备（#6 迁移中）。

## 8. 开放取舍点（已全部裁决，见 ADR-0046）

1. **对话级装配声明形态** → 会话参数（与 cwd 同等地位，分支/接续继承源会话插件集）。
2. **Agent Studio 仓库面板** → 过渡形态：数据源统一 catalog、保留开发语境专用视图、
   不成为第二装配入口；长期重做为插件产出端。
3. **全局设置插件区组织** → 按通用原则保守实现（不构成方向性决策）。
4. **ClawHost 协议冻结承诺** → 面板协议面随 agentdev minor 冻结，破坏性变更升
   major 并保留一个 major 兼容垫片。
5. **panelPrefs 存储介质** → 与呈现配置共用服务端基础设施，同期实现（实现细节）。

## 9. 落地顺序（与 P4 任务对应）

1. 插件卡片「设置」入口 + 设置弹窗（复用三态编辑器，解决配置入口层级痛点）
2. 全局装配入口 + 可见性按装配层级合成（三级体系主体，含 scope 降级调整）
3. 数据面请求上下文（多空间多 vault 联动）
4. 呈现配置迁移 + panelPrefs 契约（同款基础设施，一起做）
5. 禁用语义（#7）、懒解出自愈（#9）、卡片视觉分层、术语收口
