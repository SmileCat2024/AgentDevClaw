# 故障排查

按症状定位问题域，先做对应检查，再决定是否报告问题。排查时结合右侧栏「日志」面板（当前会话的运行日志，支持按等级筛选）与「功能」面板（能力与工具装载状态）获取证据。

## 症状速查

| 症状 | 先检查 | 说明 |
|---|---|---|
| 模型调用报 401 / 未授权 | 凭证是否过期 | 重新登录或更新 API key，会话自动恢复使用新凭证；见 references/models.md |
| 模型响应超时 / 中途停顿 | 代理与网络 | 默认 120 秒首响应、60 秒流式间隔、自动重试 5 次；持续失败先测代理连通性（设置 → 网络代理） |
| 界面打不开 / 服务未启动 | 端口占用 | 本地服务默认使用 1420（主界面）与 2026 两个端口；被占用时按系统方法释放端口后重启 |
| MCP server 的工具没出现 | 配置格式、Feature 开关与加载时机 | 项目级 stdio 需显式 type / transport；见 references/mcp.md「验证与排查」 |
| MCP 工具已出现，但调用失败 | 下游应用、端口、凭证与文件授权 | 工具枚举和网关 connected 只证明 MCP 层已连接；检查实际工具返回中的 isError 和业务错误，见 references/mcp.md「端到端验收」 |
| 工具行为异常 | 「功能」面板 | 查看对应能力是否装载、工具是否注册，钩子快照里有运行时证据 |
| 桌面版右键菜单失效 | 安装完整性 | Windows「在编程小助手中打开」右键菜单失效时，用安装包重新安装即可修复菜单项 |
| 会话上下文异常增长 / 被打断 | 上下文状态条 | 「超阈值自动打断」是正常的保护机制，按 references/sessions-and-data.md 精简即可 |

## 日志在哪看

- **会话日志**：右侧栏「日志」面板，当前会话的运行日志，按等级（error / warn / info）与关键词筛选；
- **能力状态**：右侧栏「功能」面板，查看能力包、工具与钩子的实时快照。

报告问题时附上相关日志片段，能显著加快定位。

## 如何报告问题

在仓库的 GitHub Issues 提交（地址见 references/contributing.md），一份可定位的报告包含：

1. **环境**：桌面版还是源码版，操作系统；
2. **工作空间与操作路径**：在哪个工作空间、做了什么操作、预期与实际结果；
3. **复现步骤**：从稳定状态开始的逐步描述；
4. **证据**：报错原文、日志面板中的相关片段（截图或文本）。
