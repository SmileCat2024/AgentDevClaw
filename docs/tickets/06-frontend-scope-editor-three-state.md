# Ticket 06 — 前端多作用域三态配置编辑器

- 依赖：05（数据源）、02（清洗后的全局层）
- 仓库：Claw
- 涉及：`public/src/modules/feature-setup-ui.js`（主改造）、
  `public/styles/`（三态样式）

## 背景

现状 feature-setup 面板只编辑全局，且保存是全量 dump——这正是影子写入的
源头（02 清洗后若不改此，成果立即被污染）。本 ticket 落地三态可感知编辑，
是整个"覆盖可感知"体验的最终交付面。UI 范式参照 VS Code Settings。

## 任务

1. **作用域选择器**（面板顶部）：
   - 全局 / 编程小助手的各目录（从 resolved API 的 layers 或 phProjects
     获取列表）
   - 选择后整面板进入"编辑该层"视角

2. **三态渲染**（每个字段控件）：
   - **出厂默认**（灰显，值来自 manifest default）：控件初值 = merged 值
   - **继承**：本层无该字段但上游有 → 显示上游生效值 + "继承自 <层名>"标注
   - **覆盖**：本层有该字段 → VS Code 式左侧标记条，悬停显示上游值对照
   - 三态判定数据全部来自 resolved API 的 layers.sparse + provenance +
     manifest defaults，前端不自算合并

3. **保存 = diff only**（D9 核心）：
   - 只提交用户本次会话真正碰过的字段所构成的该层稀疏内容
     （碰过 = 改过值 / 显式点了重置）
   - 未碰字段即使在控件里显示，也绝不写入层文件
   - 提交走 PUT /protoclaw/feature_config/layer

4. **值同提示**（D8）：
   - 用户改出的值 == 上游生效值时，保存前提示二选一：
     "清除本层覆盖（继承）" / "保留锁定（pin）"

5. **重置为继承**：单字段按钮，效果 = 从本层稀疏内容删除该字段

6. **warnings 透出**：resolved 返回的 warnings（如历史 null）在面板顶部
   以提示条展示

## 验收标准

- 手动测试剧本：
  1. 全局层设 lsp.typescript.mode=exec；目录层不改 → 目录视角显示"继承自全局(exec)"
  2. 目录层改为 runtime → 出现覆盖标记，悬停显示 exec
  3. 改回 exec 并选"清除覆盖" → 目录层文件中该字段消失（cat 验证稀疏）
  4. 选"保留锁定" → 字段留在文件中（pin 生效）
  5. 只碰一个字段的编辑会话，保存后层文件 diff 恰好只有该字段
- 层文件经上述操作始终保持稀疏（无空串/未碰字段回流）
- 无任何层文件时（全新环境）面板可正常编辑全局层，行为不劣于现状
