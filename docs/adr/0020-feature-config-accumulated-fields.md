# ADR 0020: Feature 配置累加型多值字段的跨层叠加

日期：2026-09-30
状态：已接受

## 背景与问题

Feature 配置队列（ticket 00，`resolveFeatureConfig` 规范 3 / D5）规定数组字段整体替换：后层胜，绝不按索引合并。这对有序列表（`lsp.runtimes`）是正确语义，但对**累加型多值字段**产生反直觉结果：工作空间 agent 层给 `skill.extraDirs` 配置了技能目录，某项目目录层再配置自己的目录时，目录层的一条数组会**整个顶掉**上游配置——用户预期是"这个目录再多扫一个目录"。

典型事故场景：Linux 服务器上 `/etc/codex/skills/` 配在 agent 层（组织级共享技能），项目目录层想追加项目私有技能目录，结果共享技能全部消失，且 merge 无任何警告，只能从"读不到技能"倒查。

## 决策

### 1. 累加型字段恒叠加，不做下层覆盖机制

产品裁决：多选字段的语义天然是累加——下层条目**追加**到上游之后，不存在"用本层列表替换上游"的用法，因此不提供任何覆盖 / 清除指令（显式拒绝 Kustomize 式复杂度）。语义：

- 跨层按序 concat，上游在前、下层追加，精确去重（首个出现位置保留）
- 非数组贡献（null / 标量）不贡献条目；null 不承担"清空上游"语义
- 空数组等价不写（无操作）
- 未登记的字段（含全部有序数组）维持整体替换不变

### 2. 实现位置：Claw 层组装侧预折叠，框架 merge 规范不变

框架设计明确"框架不认识层"（`feature-config.ts` 头注：层序与层语义是产品职责）。跨层叠加本质是**层组装语义**，因此在 Claw 侧、进入 `resolveFeatureConfig` 之前折叠（`server/shared/feature-config-accumulate.js`）：

- 策略表 `ACCUMULATED_FIELD_PATHS`（当前仅 `skill.extraDirs`，可扩展）
- 折叠动作：收集全部层的数组贡献 → 去重并集写回**最后一个提及层** → 交由既有"数组整体替换"得出 merged。merge 规范本身零改动
- 三个调用点（programming-helper agent.js / coder-agent.js / server resolved API）共用同一折叠，保证运行时行为与 UI 预览一致

否决的替代方案：**框架原生**（manifest 声明 `merge: 'union'` + `resolveFeatureConfig` 加 per-path 策略参数）——是长期归宿，但需要 core 发版，且当前只有一个累加字段；当生态 feature 也需要声明累加字段时再升级，届时策略声明权随 feature manifest 走。

### 3. 编辑器呈现：上游只读 + 本层追加

三态编辑器（feature-config-editor.js）对累加字段：

- 上游层贡献的条目以只读块展示（不可删改，标注来源层），resolved API 以 `accumulatedFields` 清单下发策略，前端不维护平行清单
- 本层可编辑输入**只承载本层条目**：跟随态不把上游值放进输入框（否则一次编辑会把上游条目抄进本层），上游生效值由只读块表达
- 只读条目计入 maxItems——总量上限作用在合并结果上（`skill.extraDirs` 运行时 `slice(0,5)`）
- 重置按钮语义不变：仅清空本层条目，回到跟随，上游不受影响

### 4. 不做清单（显式边界）

- **下层清除上游**：不做。需要"此项目不加载上游技能"时，在上游层删掉该条目，或将来出现真实需求再议
- **层内"先清后设"**：单层单 key 单值，天然不支持；叠加语义下也无需要
- **per-feature 叠加开关**：策略表是全局登记制，不提供配置项——叠加与否是字段语义，不是用户偏好

### 5. 失效信号

- 出现第二个需要跨层叠加的字段属正常扩展（加表项）；出现"生态 feature 的 manifest 需要自带叠加声明"时，本设计的 Claw 侧策略表成为漂移点，应升级为框架原生方案
- 出现真实的"下层清除上游"需求（如安全隔离：项目目录必须屏蔽组织级技能目录）时，重开此决策

## 后果

**正面**：目录层追加技能目录不再吞噬工作空间级配置；运行时与 UI 预览同源一致；merge 权威实现零改动，框架不需要发版。

**代价**：策略表与 feature 定义分离（`skill.extraDirs` 登记在 Claw 侧而非 SkillFeature manifest）——单一登记点、有失效信号兜底；resolved API 的 provenance 对累加字段指向"并集写回层"，单层归因不再精确（编辑器以只读块按层展示真实来源，provenance 不是该字段的主呈现）。

**中性**：既有层文件无需迁移——未折叠前的行为本就依赖整体替换，叠加只改变多层同时提及时的结果。
