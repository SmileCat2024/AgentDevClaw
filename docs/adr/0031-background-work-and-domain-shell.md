# ADR 0031: 后台工作的薄接入层与领域 Shell 的独立组合

日期：2026-10-21
状态：已接受；执行关联、Bash/Coder 薄接入与面板协议已实施。领域 Shell 修订为 Bash AST 解释执行（变量、循环、条件等），取代早期字面量分段基座；构建及隔离定向验收已通过，扩大回归与本次改动重启后的在线验收另记实施计划。
实施计划：[后台接入与 Coder 非阻塞监视](../plans/2026-10-21-background-work-and-coder-monitoring.md)

## 背景

Coder 线程由宿主执行，但当前 `coder_shell` 的 `send` 默认等待执行落定，`watch` 也在工具调用内阻塞。多线程监视虽然减少调用数量，主 Agent 仍需不断续挂，难以在等待期间处理其他工作。现有后台 Bash 已具有另一种交互：启动后返回，Agent 可继续工作，主动待命或自然结束轮次后，由通知唤醒。

两者需要共享异步交互保障，但不应共享 Bash 的任务模型。Bash 观察进程输出、退出码、静默与关键词；Coder 观察指定执行、线程接力、失败和需干预的状态。将 `BgRegistry` 直接推广成统一任务管理器，会把进程控制和输出监控语义带给无关领域。

同时，领域 Shell 的命令组合与后台等待是不同问题。命令回执成功不等于外部工作成功；若让脚本在外部工作期间挂起、保存变量与执行位置、唤醒后自动续跑，就会形成另一套工作流执行器。

## 决策

### 1. 核心保持通用，提供薄的开发者接入能力

复用 [ADR-0019](0019-turn-suspension-semantics.md) 的 `PendingWakeup`、`registerPendingWorkProvider`、`collectPendingWakeups` 和 `suspended` 语义。core loop 不认识 Coder、线程归档、进程静默或领域监控周期，不新增 Coder 专用接续钩子。

框架提供一个薄的后台接入层，帮助 Feature 统一衔接以下责任：

- 登记和释放待唤醒工作，向既有 pending-work 事实层申报。
- 登记显式待命意图，在安全的轮次决策边界让出执行权；自然结束轮次仍使用既有挂起判定。
- 接收领域提交的通知，交给注入的唤醒投递接口，处理登记、待命、完成和投递之间的通用时序。
- 清理自身登记和投递资源，显式暴露未送达或接入失败，避免把投递失败伪装成已通知。

职责契约由 AgentDev `packages/core/src/core/background-access.ts` 的 `BackgroundAccess` 承接，Bash 已接入；具体接口与当前交付边界见实施计划。它不进入核心循环。HTTP、宿主寻址等具体 IO 通过接口注入，不让 core 反向依赖 Claw、ViewerWorker 或 shell-feature。

该接入层不负责启动业务、识别业务终态、轮询数据源、制定汇报节奏、持久化业务状态或提供统一的停止操作。它不是全局消息总线或工作流引擎。

### 2. 领域 Shell 与后台接入层独立可用

领域 Shell 基座以 `just-bash` 的 Bash AST 与解释器执行变量、数组、循环、条件、函数、算术、命令替换和管道；领域策略继续持有动词表、参数约束与 adapter。执行前检查完整 AST 的命令入口与已知参数，展开后的参数在每次 adapter 调用前复核。命令名静态明确，禁止 `eval` / `source` / `exec`、任意外部命令、进程替换与后台 `&`，不使用系统 Bash 执行或旧字面量解析 fallback。文件重定向只访问 workspace 相对路径，拒绝路径逃逸与符号链接。解释器只提供明确列出的辅助命令，不开放其默认完整命令集、网络或 JS/Python 执行。

后台接入层负责跨轮次等待与唤醒。二者均可单独使用，业务适配器按需要组合它们。

推荐路径是：领域命令完成提交或查询后快速返回，持续监视交给后台能力。领域 Shell 可以提供登记监视、查询和待命的命令入口，但解释器本身不承载监控循环。

长时间阻塞的领域命令仍是合法实现，不设“领域 Shell 一律不能等待”的硬限制；开发者应明确其占用工具等待的代价。命令返回究竟表示“已提交”还是“已执行完”，必须固定、可解释，不能根据耗时隐式改变。

### 3. 不建设可挂起续跑的脚本执行器

Bash 控制流围绕命令本身的退出状态执行。`for` 可以连续派发，`while` / `until` 可以依据本次调用内的变量或命令状态判断，不需要脚本挂起。例如 Coder `send` 的成功表示提交成功，`send A && send B` 不承诺 A 的业务执行成功后才派发 B。脚本总状态采用 Bash 的最终退出状态，外层领域回执另外保留此前失败与未执行边界；管道和命令替换只传命令输出，不夹带回执格式。

本次不保存领域脚本的执行位置、循环现场或变量以等待未来业务结果。需要“等 A 完成，再决定 B”时，由主 Agent 收到通知后继续组织。未来若出现确定性的无人值守长流程需求，另立设计，不夹带进 Shell 语法扩展。

显式待命仅在当前工具调用完整返回后的安全边界生效，不在一条组合命令中途打断剩余命令，也不把后台业务取消作为工具返回的副作用。

### 4. Coder 后台化的是监视，不是执行实体

Coder 的权威执行和线程生命周期保持原样；不用通用后台任务再包一层 Coder 执行状态机。

已实现的命令交互如下（构建后需重启 runtime，服务端事件字段变更需整体服务重启）：

1. 正常派发确认提交后，默认登记本次执行的后台监视并快速返回；保留明确的仅投递方式。Coder 不照搬 Bash 的前台等待预算或短结果捕获窗。
2. 登记监视不结束主 Agent 当前轮次，允许继续派发和处理其他工作。
3. `watch` 表达主动待命：确保目标已被观察，登记待命后返回，由安全边界结束轮次。目标已经落定时直接返回现状，不等待下一条永远不会到来的事件。
4. 模型自然结束且仍有待唤醒工作时，结果为 `suspended`；不以“有没有输出文字”判定待命。
5. 默认在本次执行完成、失败、需要调度干预的阻塞或监视失效时通知。正常工具活动和正常接力更新状态，不逐条唤醒；可选周期汇报归 Coder 自己的监控策略。
6. 主 Agent 忙时通知进入既有输入队列，不抢占当前工具，也不启动并发主循环。

监视关联本次提交引起的执行，包含正常接力和挂起唤醒轮；不以线程归档为完成条件。取消监视不停止 Coder；停止执行和归档仍是领域操作。

若提交已生效但监视建立失败，必须保留并返回真实提交回执和监视失败事实，提供重新监视路径；不得自动重发任务。重复提交的幂等语义保持不变，重复观察不得制造重复终态通知。

### 5. Bash 保留领域能力，面板独立可选

Bash 仅迁移共同的 pending-work、待命和唤醒衔接；进程生命周期、前台预算、短结果捕获、输出采集与增量游标、周期/静默/关键词策略、stdin、停止进程树和现有通知效果继续由 shell-feature 持有。

面板不作为后台机制的前置条件。沿用 [ADR-0018](0018-feature-panel-communication-transport.md) 的通信投影，由 Claw 定义频道协议并负责渲染，Feature 可选接入并按协议发布，不提供渲染模板。同类 Feature 复用协议，通道仍按会话与来源隔离。进程类保留现有展示和按钮；智能体类本期只展示状态，不提供反向控制。面板失败不能影响执行、监视与唤醒，不将展示协议放入框架后台逻辑。

### 6. 接续先保证监视失联可发现、可重建

区分主 Agent 的监视资源与 Coder 执行资源。主 Agent 会话接续或监视资源释放，不代表 Coder 停止。

本期最小承诺：此前存在监视意图、当前已无有效监视时，后继 Agent 能收到明确的重新监视提示。重建先查询执行现状：运行中重新观察，已结束取回结果，不重发原任务。检测依据不能只是“状态不存在”，否则首次启动与普通无监视会话会误报。

使用现有 Feature 状态快照、连续性或宿主生命周期接入点完成检测；具体载体在实现前核验，不添加 Coder 专用 core-loop 原语。不承诺透明迁移监视、持久化通用通知队列或 Claw 重启后的自动恢复。旧接收者的迟到通知不得误投到其他会话。

## 实施顺序与验收边界

先交付薄的后台接入能力，以 Bash 与 Coder 两个真实接入验证；再单独扩展领域 Shell 命令组合。第一阶段不顺带重写 Bash 引擎，第二阶段不建设脚本挂起续跑。具体步骤与测试见实施计划。

Coder 工具的新默认行为属于明确替换旧行为：实现发布时同步更新工具描述、技能、相关测试和调用方，不暗留两套默认路径。是否存在必须维持的外部契约须先盘点；有则明确讨论，不自行添加兼容 fallback。

## 与既有决策的关系

- **ADR-0019**：保留挂起事实与优先序；第二个真实消费者使薄的多源接入层具有现实用途，但不触发统一业务任务管理面。其“runtime 结束即任务结束”限定为原 Bash 进程语境，不能推广为“主 Agent 结束即 Coder 停止”。
- **ADR-0018**：保留状态真相与面板投影分离，不把尽力而为的面板通道当可靠唤醒队列。
- **ADR-0005**：工具超时、用户打断仍按终止结果契约返回；后台观察的停止与外部业务的停止由领域明确区分。
- **ADR-0028**：通用契约与生命周期衔接归框架，具体宿主 IO 与资产归应用；无需为普通复用把 Claw 控制协议塞进 core。

## 取舍与不做

收益是：Agent 不必持续占用工具等待，开发者无需重复拼接通用时序，领域仍可保留精细监控。

代价是：提交回执与业务完成需要明确区分；Coder 监视必须建立可靠执行关联；跨仓交付须同步装配和教学。薄接口需要真实双接入验证，不能只用模拟消费者宣称抽象成熟。

不做统一业务状态机、统一监控周期、统一 kill、统一任务表或强制面板；不做脚本续跑、自动重新派发、透明跨接续监视迁移、服务重启恢复和通用持久通知服务。
