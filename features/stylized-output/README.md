# stylized-output

输出风格库 + 确认签名门禁。用户用 markdown 预置输出风格；风格被选中后，模型的每一次最终回复都必须调用签名工具逐字默写该风格的确认签名，验证通过才允许结束本轮回复。

## 目录约定

风格来自两个来源合并发现，同名时工作区版本优先（用户自定义覆盖内置）并记录警告：

1. **feature 内嵌**：`src/styles/*.md`（构建时经 copy-assets 镜像到 `dist/styles/`，随包分发）
2. **工作区**：`<workspaceDir>/.agentdev/output-style/*.md` —— 每个平铺 md 文件 = 一种风格（非递归、忽略点开头的文件）

## 风格选择的生命周期（会话作用域，不落盘）

风格选择是**会话内存状态**（`activeStyleName`），没有任何磁盘存储：

- 选择/清除的唯一写入入口是 `configure` capability（Claw 面板 / slash，人工操作，即时生效）；模型侧没有设置风格的工具。
- 同一会话内随 Feature 状态快照（`captureState` / `restoreState`）持久：Runtime 停止重启恢复 stateful 会话时，选择一并还原。
- **默认风格回填**：配置了 `defaultStyle`（构造 options / manifest settings / featureConfig，三通道同 `maxSignatureBlocks`）时，会话未选择风格且未被显式清除，扫描后自动启用默认风格——新会话、接续会话、存量会话恢复统一适用，无需每会话手动设置。配置界面中它是下拉选择，选项只列 feature 内置风格（声明时扫描内置目录生成）；运行时的风格发现与选择不受此限，仍为双源合并。
- **显式清除不被拉回**：面板清除选择会记 `activeStyleCleared`（随快照持久化），此后默认风格不再自动回填——区分"没选过"与"不要了"。旧快照无此字段按未清除处理，存量会话恢复后同样获得默认。
- 内存中选中的风格文件被删除/改名时，下次扫描自动按未选择处理（门禁旁路）并记录警告。

## 风格文件格式

```markdown
---
name: 简洁汇报
description: 一句话描述。
signature: 我确认本回复已经过逐句删减，没有一个多余的字。
---

（正文：风格规则）
```

frontmatter 必填 `name` / `description` / `signature`（均为单行字符串，含冒号时建议加引号）；缺字段或重名的文件会被忽略并记录警告。`signature` 是确认签名：一句简短但独特的声明句，是本 Feature 的核心创新——模型必须逐字默写它作为合规证明。

## 行为

1. **注入**：风格被选中时，风格全文（frontmatter 原文 + 正文 + 签名要求）以 system 消息注入上下文；风格或其文件内容变化时重新注入（内容指纹去重）。
2. **签名工具 `sign_output_style`**：模型逐字默写当前风格的 signature，规范化空白后全等比对。匹配 → 本轮放行；普通签名的成功提示同时引导自然收尾（面向用户的回复已完整输出时不必复述全文，简短几句交接即可；尚未输出时再输出完整回复）；不匹配 → 报错并要求核对原文（不泄露正确签名）。未启用风格时调用会得到明确的"无需签名"拒绝。
3. **门禁（StepFinish guard）**：风格启用期间，无工具调用的自然结束步必须已签名通过；否则拦截结束，提醒模型复核已有输出：符合则直接签名，不符合时作必要补充或局部改述，无需全文重写；提醒包含当前风格名与 `show_output_style` 重读入口。本轮触发过拦截后，成功补签在 StepFinish 正常结束当前回复，不再额外调用模型收尾；可以先查阅风格再补签，普通签名与失败签名不会自动结束。连续拦截达到 `maxSignatureBlocks`（默认 5，1–10）后放行并告警，防死循环。子代理或 wait 机制活跃时不干预；结束仍经过框架排队输入检查，后台工作仍由框架判定挂起，不使用 `interrupt()`。
4. **管理工具 `list_output_styles` / `show_output_style`（只读）**：模型可主动列出全部风格（名称 / 描述 / 是否启用），或查看指定风格（缺省当前风格）的完整说明原文（frontmatter + 正文 + signature）。上下文中的风格说明被精简或遗失时，凭这两个工具即可重新核对签名原文与风格要求。
5. **会话状态**：风格选择与签名凭证均为会话内存态；签名凭证与补签收尾条件在 CallStart、风格切换或新用户消息进入模型前清零，包括同一次 call 内的排队插话。状态随会话快照持久化，跨会话不继承。

## 公共 API（供控制面 / 其他 Feature 使用；模型不可见）

- `getStyles()` / `getActiveStyle()` / `getStatus()`
- `setActiveStyle(name | null)` —— 设置/显式清除当前风格（会话内存态，立即生效，不落盘）；面板 capability 的写入入口，清单外的风格名会被拒绝；显式清除后默认风格不再自动回填
- `setMaxSignatureBlocks(value)` —— 调整签名拦截上限（1–10 钳制）

对外控制链路是 `configure` capability（Claw 面板 / slash）：读取门禁状态、切换风格、调整签名拦截上限。

## 测试

自动化测试：`node --test test/stylized-output.test.js`（构建 dist 后运行），覆盖：

- 签名匹配 / 空白规范化匹配 / 不匹配拒绝 / 空参数拒绝 / 未启用风格拒绝
- 门禁：普通工具步不干预、已签名自然结束放行、未签名拦截及复核文案、拦截后成功补签收尾、失败重试与重读风格、连续拦截达上限放行
- 边界与集成：CallStart / 风格切换 / 排队用户输入重置、快照往返、真实框架模型调用次数、工具结果落入上下文、同批独占工具约束、排队输入不丢失、后台工作挂起
- 内置风格：内嵌与工作区风格合并发现、重名时工作区优先、默认风格回填、清单外默认保持未选择、显式清除后不回填、清除标记随快照往返、旧快照恢复后回填生效、featureConfig 通道声明默认

集成测试通过 `defaultStyle` 启用风格，使用脚本化模型响应与隔离的排队输入驱动真实 Agent 生命周期，不访问在线模型或真实 ViewerWorker。面板选择、真实模型遵循提醒的效果仍需在线人工验证。
