# ADR 0032: 编程小助手线程驱动——对话身份从 Session 提升为 Thread

日期：2026-10-24
状态：已接受（实施工单见 [docs/tickets/2026-10-24-ph-thread-driven.md](../tickets/2026-10-24-ph-thread-driven.md)）

## 背景与问题

编程小助手（智能编码空间主 APP）当前把「对话」等同于 Session：列表行、聊天视图锚、输入路由、搜索聚合都以 Session 为身份。`/trim` / `/summary` 精简创建新 Session 并归档源会话，前端执行完整导航切换到新会话（trim-page 现状）。由此产生四个体验断点：

1. **精简是搬家式页面切换**：页面跳到「另一个会话」，滚动位置与思路被打断——ADR-0024 点名要消灭的「切换感」在编程小助手每次精简时都在发生。
2. **列表碎片**：本机实测（2026-10-21 快照）2606 条会话含 1097 条接续血缘边、501 条多代逻辑链、最长 17 代——一段对话在列表里占 17 行历史。
3. **精简过程输入无保障**：变换进行期间的输入没有暂存机制，可能投给即将退役的旧会话。
4. **代际关系不可见**：旧代以普通归档记录散落，UI 无处表达「这 N 条其实是 1 段」；搜索按 Session 聚合导致跨代重复命中。

两阶段计划（2026-10-21 会话确认：先项目化、再线程化）的第一阶段（041–047，目录对话与项目对话并存）已完成：归属（`openDirectory` / `projectId`）与配置分层就位，且显式排除线程化。本 ADR 是第二阶段。

基础设施已就绪：`threadHost` 声明驱动宿主注册（[host-agents.js](../../server/thread-control/host-agents.js)）；thread-integration 钩子链（建线 / 接续挡板与 head 推进 / 删除守卫 / 输入网关路由）以「会话是否为活跃线程 head」为唯一判定，与 APP 无关；coder 与 memo 已作为消费者验证。

## 决策

### 1. 对话身份 = Thread，声明驱动接入

- PH metadata 声明 `threadHost: true`；新会话（含 branch 产生的新会话）自动建立线程，会话成为 root 与初始 head。
- **目录对话与项目对话一并覆盖**：`threadHost` 是 APP 级环境开关，与 `projectId` 归属正交。042 交付的派生继承（分支与接续继承来源归属）在线程域不变。
- coder 与 memo 行为零改动。

### 2. 接续入口：手动事务化；自动触发不在本 ADR

- `/trim` `/summary` 与精简配置页**保留**，行为改为**对话内接续**：触发线程 succession 事务（挡板 → 变换 → successor → head 推进），不再产生「新会话 + 导航切换」的体验。变换参数（模式 / 比例 / 摘要选项）沿用现有精简页。
- slash 命令 `applies` 谓词调整：现状对线程宿主会话一刀切隐藏手动命令（coder 口径，因其有自动接续）；编程小助手保留手动入口——谓词按「是否装配自动接续」或 APP 声明显式区分。
- 上下文阈值自动接续（coder 的 ContextRotationTriggerFeature 同构）与 adaptive 轮换策略为后续独立决策；本 ADR 期间上下文提醒沿用 context-guard 既有提示。

### 3. 前端：对话锚 + 时间锚历史存档

- **列表行 = 对话（Thread）**：显示当前 head 的标题 / 预览 / 时间。混合渲染期内未迁移的 Session 行是「没有历史的对话」的自然特例，不做伪线程包装（ADR-0026 统一契约的精神）；迁移批完成后过渡态自然消失。
- **历史存档用用户语言，不用实现语言**：不出现「第 N 代」。对话行提供「历史 · N」入口；「历史记录」是按时间倒序的存档列表，每项是**一次精简发生之前的完整对话原貌**，以时间锚 + 触发方式标注（如「10 月 23 日 21:14 · 精简前的对话」+ 裁剪比例 / 摘要方式 + 当时的规模）。存档只读，提供「从这段继续」（= 分支 = 新线程，标注分出来源）。
- **接续等待与换头**：复用既有接续等待表面与数据源重绑。ADR-0024 硬切换裁决适用：页面不离开、滚动 / 草稿 / 焦点不动、变换产物如实呈现（精简主干 / 摘要作为当前对话的开头，无额外接缝 UI）、不跨 Session 拼接历史。
- **输入改线程寻址**：服务端解析当前 head（健康直投 / 接续窗口暂存 Inbox）。前端不再自行计算目标 Session。
- **侧栏零改动**：ADR-0010 三层投影天然覆盖（叶子 = 运行中 head 会话的 runtime）。
- 接续后旧 head 的会话归档状态沿用现状（trim 归档源会话）；历史存档入口独立于归档区呈现，不依赖会话归档字段。

### 4. 存量迁移：机制先行、迁移第二步

- 机制批上线后**新会话即刻线程化**；存量迁移作为独立第二批执行，两批分别验收。
- **终态全量**，含已归档会话（约 67%）——归档区与搜索按对话聚合的前提。
- **血缘口径**：index `metadata.sourceSessionId` + `resumeMode: 'compacted'`（接续边）、`metadata.branchSourceSessionId`（分支边，存量预计为零——该字段从未落盘，故链数为下限）。**排除项**：`resumeMode: one-shot` 的派生子代理会话、无索引记录的孤儿文件。
- 无证据单例各自成单代线程——统一体验要求列表行概念一致（「没有历史的对话」是自然特例，不是待处理的旧形态）；歧义关系（多后继、悬空边）生成人工确认清单，不自动合并——**宁可多建线程，不猜错合并**。
- **执行纪律**：先备份、生成预览清单、确认后执行；幂等可重跑（中断重跑不重复创建）。不做 UI 产品化，脚本 + 清单文件 + 人工确认。

### 5. 会话移动 = 整链移动

「移动对话」在线程域改**整条线程**（head + 全部历史代）的归属转移，不是只移 head。沿用 046 的执行中拒绝与空闲判定，判定对象从单个会话扩展为「线程无执行中轮次」。

### 6. 治理与配套

- **不声明 `maxLiveThreads`**（缺省不限额）：交互式对话不适用 coder 的「干完归档释放名额」纪律，用户不会主动归档。
- **搜索按 Thread 聚合**（结果聚合、跨代去重、归档状态认准线程、命中位置绑定内容版本）为独立后续票，不阻塞本批。

## 不做清单（显式边界）

- 不做自动阈值接续与 adaptive 轮换策略（后续独立决策）。
- 不做搜索 Thread 聚合适配（独立票）。
- 不做跨 Session 拼接的单流视图（沿用 ADR-0024 裁决：当前视图只呈现当前 head 自己的记录）。
- 不做任务看板等 coder 专属能力。
- 不改消息存储与会话文件格式（消息永远属于 Session 文件；Thread 只持有关系与生命周期事实）。
- 不改 coder / memo 的任何行为。
- 不做 ADR-0026 未尽实施项的系统性重构（只消费既有契约；实施中发现缺口按该 ADR 的实施顺序补，不顺手扩大）。
- 不做跨目录对话转移、外围入口（ACP / CLI / 桌面右键 / 调度 / 群聊）的项目化对接扩展（沿用 041–047 边界）。

## 后果

**正面**：对话身份稳定后，四个断点（切换感 / 列表碎片 / 输入黑洞 / 代际不可见）结构性消失，而非逐个打补丁；机制批复用已验证的声明化基础设施，新增面集中在 PH 前端投影与列表接口；存量迁移是纯关系数据写入，不搬正文。

**代价**：混合渲染过渡期（迁移批完成前列表双形态并存——以「对话」统一行概念把过渡成本压到最低）；存量迁移是一次性数据事务（备份 + 预览 + 幂等对冲）；`/trim` `/summary` 谓词与精简页提交行为需要改造；前端列表接口需要新增线程分组投影。

**风险与失效条件**：

- 存量血缘证据不全（branch 字段从未落盘，多后继歧义）→ 迁移预览清单人工确认兜底；悬空边目标端按链根处理。
- 混合渲染期若无限期悬置会成为长期双轨 → 迁移批是机制批验收后的立即下一步，不排队等待。
- 精简页参数与线程 succession 事务的对接若有缝隙（挡板未生效即导航）→ 049 票验收必须覆盖「精简期间输入暂存」与「换头后页面状态连续」的真实浏览器场景。
