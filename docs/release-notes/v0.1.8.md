# v0.1.8 更新公告

本次更新涵盖自 v0.1.7 以来的全部改进，包含 27 次提交。

本轮的核心变化是**模型配置从启动时静态绑定变为运行时动态可变**。此前，Agent 的模型、思考力度等参数在进程启动时确定，切换需要重启；本版引入了完整的热切换基础设施，用户在对话进行中即可切换模型预设与思考力度，Context Guard 阈值也会随模型上下文窗口自动调整。这一交互范式的转变贯穿了从服务端 IPC、模型预设解析、Context Guard 到前端输入工具栏的全链路，大量调整与修复都是这条主线的涟漪效应。

此外还包含 CallArbiter 输入队列单路径治理、Todo 打断链路修复、UI 视觉品质升级等方向的工作。

## 新特性

- **LLM 模型运行时热切换**：无需重启 Agent，在对话进行中即可切换模型预设。点击顶部上下文栏展开模型下拉面板，展示模型名称、视觉能力标识与上下文长度（如 128K），选择后即时生效：
  - 服务端新增专用 `POST /protoclaw/swap_model` 端点，负责写入配置（重启后持久）并向运行中 runtime 投递 swap-model IPC
  - 框架侧移除 mid-turn swap 限制（`setLLM()` 不再在活跃调用中抛异常），热切换在对话进行中同样可用
  - Context Guard 阈值随模型上下文窗口自动调整，切换大窗口模型时不会因旧阈值误触中断
- **思考力度运行时热切换**：输入工具栏模型切换器旁新增思考力度按钮，支持在 Default / Minimal / Low / Medium / High / Max 之间即时切换，运行时覆盖不修改 preset 定义：
  - `resolveModelPresetLLM` 新增 `overrides` 参数，将运行时思考力度覆盖注入 LLM 创建流程
  - 模型预设新增 `thinkingEffort` 字段，每个预设可独立声明默认思考力度
  - IPC 支持按会话/运行时定向投递，避免全量广播影响其他 Agent
- **自定义下拉组件（claw-select）**：替换原生 `<select>`，统一下拉面板视觉风格，支持滚动、高亮、SVG 图标嵌入，服务于模型切换与思考力度切换场景
- **设置面板布局重构**：改为固定横幅 + 可滚动内容区 + 底部操作栏三段式布局，模型配置项从手动保存/取消改为下拉框自动保存，交互更直接

本轮对界面整体视觉层次做了系统性优化：

## 问题修复

### 模型热切换数据管线

- **agentId 解析错误导致热切换间歇性失败**：`_getInputAgentId()` 返回的是 ViewerWorker 子进程 UUID 而非 host agent ID，导致配置写入与 IPC 投递找不到目标。改为以 `currentAgentId`（host ID）为主
- **modelPresets 在 runtime 合并后丢失**：runtime 子进程记录不含 modelPresets，导致默认预设查找失败。合并时从 host 记录携带
- **thinkingEffort 在 5 处传递点丢失**：模型预设解析、LLM 创建 meta、overview 快照归一化、持久化输入缓存——页面刷新 / 会话切换 / Agent 重启后思考力度开关回到默认值。全链路补齐
- **thinkingEffort 跨 provider 不兼容**：从 Anthropic 切换到 OpenAI 时，存储的 `max` 值对新 provider 无效。切换时校验当前 provider 合法值，不兼容时回退到预设默认
- **thinkingEffort 跨模型继承**：思考力度覆盖写入 agent config 后，切换到其他模型时仍然继承旧值。改为始终从当前 preset 读取，不做跨模型继承
- **metadata.json 校验阻止动态 Agent 切换模型**：PUT 端点对 metadata.json 的存在性校验阻塞了动态创建的 Agent（如 group-chat dispatch），配置写入与 metadata.json 无关，移除门控
- **模型配置全量校验死锁**：一个模型的 maxTokens 误改后导致整个配置无法保存。移除服务端阻塞式校验，改为前端字段级实时校验（输入框描边变红 + 文字警告），仅做视觉引导不阻塞保存
- **swap-model IPC 残留 isRunning 守卫**：框架已移除 mid-turn swap 限制，但 IPC handler 仍在 `isRunning()` 为 true 时静默跳过

### Todo 打断/停止机制（三个数据链路 Bug）

- **跨会话路由串台**：`sendTodoControl` 用 OR find 误匹配 workspace host session，`/todo_control` 路由回退到 `pickPrimaryAgentRuntime` 投递到错误 session。改为按 `runtime_session_id` 精确匹配
- **僵尸断点**：精简后新 runtime 恢复 `interruptTargetId` 时，目标 task 可能已终态或不存在，导致首轮 `StepFinish` 立即触发 `Decision.Deny`。恢复后检查目标有效性，无效则清除
- **前端状态不同步**：服务端 `interruptTargetId` 更新后前端 3 秒宽限期内不覆盖本地缓存，避免用户刚点击的打断操作被轮询刷掉

### 其他修复

- **Skill 保护从 turn 级收窄为 message 级**：原实现将含 `invoke_skill` 调用的整个 turn 加入保护集，导致同 turn 全部消息（可能数百条）免于折叠。勾选全部轮次精简时含 skill 的大 turn 始终完整保留，连续精简后会话持续膨胀。Phase 2 收窄到只保护 `invoke_skill` 调用所在的 assistant 消息和对应 tool result 消息
- **CallArbiter 遗留队列消息丢失**：某些场景下（maxTurns 达上限、call 出错前队列检查未执行）react-loop 的 step-boundary 和 post-completion 检查未能消费 ViewerWorker 队列中的消息。新增 `_drainViewerQueuedInputs()` 安全网，在每个信封完成后扫描队列并补投递
- **右侧设置弹窗被中央区域遮挡**：`.main-content` 内部高 z-index 元素（user-input-container、follow-latest-btn）逃逸到根堆叠上下文覆盖右侧面板。添加 `isolation: isolate` 创建堆叠上下文隔离
